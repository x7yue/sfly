# 项目是顶层租户；人用本地账号登录，程序用令牌；权限只在契约路由一处检查

ADR 0004 的前提是「平台只在内网、每个人有自己的测试环境」，所以身份只是不校验的昵称。这个前提已经不成立：平台里要加入助手（#442），模型有 shell，能绕开任何界面直接请求 HTTP 接口，能拦住它的只有控制面上它够不着的检查；平台也要能让几个团队共用一套控制面而互相看不到。所以平台建模**用户**和**项目**：项目是顶层租户，场景、运行、节点包、飞书机器人、Agent、会话和工作台都属于一个项目；人在控制台用本地账号登录，命令行、API 客户端、Agent 和助手会话都用令牌；每个接口要什么身份、作用在哪个项目上，只在契约路由一处检查。认证默认开启，不留关闭的开关。本 ADR 取代 ADR 0004。

## 规则

### 用户、项目与角色

- **用户**是本地账号（登录名、密码哈希、是否停用），表里留一列外部身份，以后接反向代理头或 OIDC 时不用再迁移。**平台管理员**是用户上的标记：建项目、管理账号、维护公共项目，并在每个项目里拥有项目管理员的权限（项目最后一位管理员离开时靠它恢复）。这是「另一个项目读不到」的例外，拦不住（他本来就能登录主机、重置任何人的密码），但要对项目透明：平台管理员在自己不是成员的项目里做的写操作都留下记录（谁、什么时候、做了什么），项目的成员看得到。
- **项目**有不可修改的标识（小写字母、数字、连字符，出现在路径里）和可以修改的显示名。迁移时建两个：**默认项目** `default`，现有的数据全部归它；**公共项目** `public`，放平台维护的节点包（标准节点包，#454），任何凭据都能读、任何项目的场景都能引用，只有平台管理员能发布。
- **成员**是用户在一个项目里的角色，只有三种：**只读**、**成员**、**项目管理员**。角色是固定的一组范围（下表），检查只看范围，不看角色名；以后要加「只能触发运行」这类角色，只是多一组范围。
- 一台机器要给两个项目用，就装两个 Agent（不同的系统用户、`SFLY_HOME`、名字和端口），隔离交给操作系统。

| 范围 | 允许什么 | 只读 | 成员 | 项目管理员 | 会话令牌 |
|---|---|---|---|---|---|
| 读 | 项目内一切只读接口（密钥的原值没有接口） | ✓ | ✓ | ✓ | ✓ |
| 运行 | 触发、取消运行 | | ✓ | ✓ | ✓（限勾选的 Agent、自己触发的运行） |
| 编辑 | 场景、场景版本、场景的设置（运行通知、关注项、运行预设）的增改与归档 | | ✓ | ✓ | ✓（限会话自己建的和勾选的场景） |
| 会话构建 | 登记会话构建 | | ✓ | ✓ | ✓ |
| 发布 | 发布节点包的正式版本 | | ✓ | ✓ | 要人批准 |
| 管理 | 成员、项目令牌、Agent 与它的凭据、飞书机器人、项目密钥、Agent 立即更新 | | | ✓ | 不能 |

### 凭据

| 凭据 | 谁用 | 属于 | 怎么带 | 有效期 |
|---|---|---|---|---|
| 登录 Cookie | 控制台 | 用户 | HttpOnly、SameSite=Lax 的 Cookie，只接受同源请求 | 空闲超时，可在账号页注销全部 |
| 个人令牌 | 命令行、API 客户端、自建页面 | 用户，可限定一个项目和一部分范围 | `Authorization: Bearer` | 可设过期，可吊销 |
| 项目令牌 | 自动化、自建页面 | 项目（服务账号），选定范围 | 同上 | 同上 |
| 会话令牌 | 工作台上的 `sfly` | 一个会话：代发起人、限一个项目 | 同上 | 随会话结束；停止会话就是吊销它 |
| Agent 凭据 | Agent | 一台 Agent（项目 + 名字固定） | gRPC `Hello.token`；Agent 请求 HTTP 时 `Bearer` | 可吊销、可轮换 |
| 任务凭据 | 任务里的 SDK（下载产物） | 一次任务尝试 | 随 `AssignTask` 下发，`Bearer` | 任务结束即失效 |

- 令牌都是高熵随机串，带种类前缀（例如 `sfly_pat_`、`sfly_ses_`、`sfly_agt_`），便于识别和在日志里打码；库里只存 SHA-256 哈希，原值只在签发时显示一次。
- **会话令牌的权限不超过发起人**：每次请求都取「会话的范围」和「发起人此刻在该项目的角色」的交集，发起人被降级或移出项目，会话随之失去权限。
- **工作台的 Agent 用自己的 Agent 凭据**（骨架阶段就做）：模型的命令读得到工作台上的凭据，按 Agent 签发的凭据只能冒充这一台工作台，拿不到别的 Agent 的任务。
- 「经 …」（`triggered_via`、`author_via`）从令牌取：会话令牌记会话，其余令牌记令牌的名称。`x-sfly-client` 只剩版本告警的用途，不再是身份。

### 项目从请求的哪里来

项目不从请求头取，也不只从令牌取：按资源怎么定位分四类（现有 74 个路由，按路由清单 `sdk/python/src/sfly/schemas/routes.json` 分）。

| 类 | 路由 | 项目怎么得出 | 数量 |
|---|---|---|---|
| 路径带项目 | 列表与新建（场景、运行、Agent、节点包、飞书机器人、控制台统计），以及按名字定位的 Agent、节点包、飞书机器人 | 路径改成 `/projects/:project/…` | 18 |
| 经场景 | `/orchestrations/:id/…`（版本、设置、预设、预检、触发） | 场景所在的项目 | 21 |
| 经运行或任务 | `/runs/:id/…`、`/tasks/:id/…`（详情、取消、日志、指标、动作、产物） | 运行所在的项目（`runs` 冗余一列 `project_id`） | 20 |
| 不属于项目 | 健康检查、文档、SDK 与 Agent 二进制、安装脚本、API 客户端安装包、Python 索引 | 不需要凭据 | 15 |

- 和 #448 的声明对得上，不另加「项目来自哪」的声明，靠一条由契约测试检查的约定：`target` 是 `collection`、`upload`，或者用名字定位（Agent、节点包、飞书机器人），路径里必须有 `:project`；用 ID 定位的（场景、运行、任务，以及以后的会话）路径里不能有 `:project`，项目从资源得出；`system` 两者都没有。
- 凭据本身限定了项目的（项目令牌、会话令牌、Agent 凭据、任务凭据，以及限定项目的个人令牌），和请求得出的项目不一致就拒绝；登录 Cookie 和不限项目的个人令牌看用户在该项目的角色。
- 资源不存在和「存在但属于别的项目」返回同一个 404，不泄露别的项目有什么。
- **SSE**：事件流本来就是契约里的路由、经同一个注册入口（`contract-route.ts:124`），订阅时做同样的检查；控制台和 API 客户端用 `fetch` 读事件流（`packages/client/src/subscribe.ts:79`），能带 `Authorization`。凭据被吊销时，控制面关掉用它打开的事件流（单进程，按凭据登记即可）。
- **Agent 的 gRPC 流**：身份在 `Hello` 时从 `token` 得出，`Hello.name` 必须和凭据上的名字一致；之后这条流上的消息都以这台 Agent 的身份处理，只接受派给它的任务的上报。协议不加字段。

### 一处检查

- **范围不逐个接口手写**，由 #448 给每个接口的声明查一张表得出。声明有 `effect`（`read` 或 `write`）、`resource: { kind, target }`（定位到哪类资源的哪一个），以及可选的 `creates`（新建的是哪类资源，只在和定位到的类别不同时写）。规则：**范围由「接口作用在哪类资源上 × 只读或写」查表得出，「作用在哪类资源上」取 `creates`（有的话），否则取 `resource.kind`；项目和会话勾选范围的检查始终用 `resource` 定位到的那个资源。**
- 范围表，以及按这条规则过一遍现有接口的结果：

  | 接口（声明） | 查表用的类别 × 读写 | 范围 | 项目和勾选按哪个资源查 |
  |---|---|---|---|
  | 所有只读接口 | 任意 × 读 | 读 | 定位到的资源 |
  | 保存版本、恢复版本、改设置（运行通知、关注项）、新建、归档与恢复场景（场景，写） | 场景 × 写 | 编辑 | 定位到的场景；新建按路径里的项目 |
  | 复制场景（场景，写，定位到源场景） | 场景 × 写 | 编辑 | 源场景：要能读它、在它的项目里有「编辑」；会话要勾选了源场景（或源场景是会话自己建的） |
  | 运行预设的增改、复制、删除（场景，写） | 场景 × 写 | 编辑 | 定位到的场景 |
  | 触发运行（场景，写，`creates: run`） | 运行 × 写 | 运行 | 场景：会话要勾选了它（或它是会话自己建的）；用到的 Agent 另由触发准入查 |
  | 取消运行（运行，写） | 运行 × 写 | 运行 | 定位到的运行；会话只能取消自己触发的 |
  | 登记会话构建（会话，写，`creates: session_build`） | 会话构建 × 写 | 会话构建 | 定位到的会话：只能是令牌自己的会话 |
  | 发布正式版本（节点包，写，`upload`） | 节点包 × 写 | 发布 | 路径里的项目 |
  | Agent 立即更新、飞书机器人的增删改与测试消息（写） | Agent、飞书机器人 × 写 | 管理 | 定位到的资源 |
  | 成员、令牌、密钥的写（随 T13、T05、T17 加入） | 各自 × 写 | 管理 | 路径里的项目 |
  | 上传产物（任务，写） | 任务 × 写 | 不给人和程序：只有 Agent 凭据，限派给这台 Agent 的任务 | 定位到的任务 |

- Agent 凭据和任务凭据也按同一张表限定，不在接口上另写「谁能调用」：Agent 凭据只有「节点包的读」（下载归档，限本项目和公共项目）和「任务的写」（上传产物，限派给它的任务）；任务凭据只有「任务的读」（下载产物，限同一个项目）。以后出现给人用的「任务的写」时，再在声明里把两者分开。
- **会话构建和正式版本走两个接口**：正式版本是项目下的节点包上传（`write`，节点包，要「发布」）；会话构建登记在会话下（定位到会话，`creates: session_build`，要「会话构建」），版本号的会话标签由控制面给，正式版本的上传拒绝带会话标签的版本号。不用同一个接口加参数或按版本号的形状区分：那样范围要看请求体甚至上传内容才能定，鉴权就不再是只看声明的一处检查，形状写错一点就会让会话构建变成正式版本。会话把构建变成正式版本，就是用会话令牌调用正式版本的上传：它没有「发布」范围，这个请求（连同上传的归档）变成待批准的操作。
- 检查放在契约路由的注册入口：解析凭据、按声明得出项目、查归属、查范围、查会话的勾选，全部通过才进处理函数。现在散在各路由里的 `requireNickname` / `requireActor`（18 处）删掉。启动守卫（`contract-route.ts:180`）同样拒绝缺声明的接口。
- 只有一处例外：触发运行时用到哪些 Agent，要解析场景文档才知道，所以「Agent 属于场景的项目、在会话勾选的范围内」由触发准入检查（预检和派发用同一个判断），它从请求拿到同一份凭据上下文。
- 有一组从路由清单生成的测试：项目甲的每种凭据访问项目乙的每个接口都被拒绝，每个接口一条，新加的接口自动覆盖。

### 助手会话

- 建会话时，人勾选这次可以改的场景和可以派任务的 Agent，控制面签发会话令牌。会话自己建的场景（联调副本）、会话构建、触发的运行记着属于哪个会话。
- 默认直接做：读项目内的东西；改会话自己建的和勾选的场景；登记会话构建；在勾选的 Agent 上触发运行，取消自己触发的运行。
- **越权的写请求变成待批准的操作**：会话令牌的写请求没通过勾选或范围检查、而这件事发起人自己有权做时，控制面不返回 403，而是把这个请求（方法、路径、请求体、会话、发起人）存成一条**待批准的操作**，返回 202 和它的 ID。可以批准的只有：发布正式版本、改动、复制或触发勾选范围以外的场景、用没勾选的 Agent、取消别人的运行。有权限的人批准后，控制面以批准人的身份把原请求重新走一遍同一条路由（乐观锁、预检照常生效），结果记在这条操作上；拒绝、会话结束都让它失效。它是数据库里的对象，控制面重启不丢。
- 不能做、也不能批准：管理范围的一切；删除或归档不是会话自己建的东西；读密钥的原值。哪些接口是删除或归档，要由声明给出（归档场景、删除运行预设、删除飞书机器人）：只看「写」区分不出来，HTTP 方法也不行（归档是 POST），所以 #448 的声明要加一个可选的 `removes`。
- 勾选范围的检查用接口定位到的资源：复制、触发一个场景，要求这个场景在勾选里或是会话自己建的（联调副本复制的就是人指定、也就是勾选了的场景）；触发时用到的 Agent 另要在勾选里。
- 会话（`session`）和会话构建（`session_build`）两个资源类别随骨架加进 `RESOURCE_KINDS`。会话令牌对会话这一类只有读：不能建会话，也不能批准自己的待批准的操作。
- 会话触发、并且用到会话构建的运行，保密参数默认不解析（运行被拒绝并写明原因），除非建会话时人勾选了「联调时可以使用项目密钥」：否则模型写的代码拿到密钥就能把它带出去，接口层的打码拦不住。

### 认证的几处细节

- **第一个管理员**：控制面启动时没有任何用户，就在日志里打印一次性的初始化码（同时写进数据目录里一个只有属主可读的文件），用它在 `/setup` 页建第一个平台管理员；自动化部署和测试可以改用环境变量给出初始管理员。离线安装不依赖邮件。管理员忘了密码，在控制面所在的主机上执行重置命令（能登录主机就已经是最高权限）。
- **密码**用 Node 自带的 `crypto.scrypt` 存哈希，参数和盐写进存储串，以后可以平滑调高；控制面是 esbuild 打的单文件（`apps/server/scripts/bundle.ts`），不能引入 argon2、bcrypt 这类原生模块。登录按用户和来源地址限速。
- **跨站请求**：登录 Cookie 只认同源请求。带 Cookie 的请求，`Origin`（或 `Sec-Fetch-Site`）表明来自别的站点就当作没有登录；控制台和控制面本来就同源（ADR 0006）。不另做 CSRF 令牌。SameSite 不够用：同一个公司域名下的其他内网站点算「同站」。
- **跨域的默认值不变**，仍允许所有来源，但永远不发 `Access-Control-Allow-Credentials`：跨域只能用请求头里的令牌，没有令牌的请求一律 401，所以「内网任何网页都能触发运行」（ADR 0022 的后果）随之消失，自建页面换上项目令牌就能继续用。CORS 允许的请求头要加上 `authorization`（现在没有：`apps/server/src/http/cors.ts:11-16`）。

### 密钥

- 平台自己存的密钥原值只在一处：项目的**密钥**表，加密存放，密钥的加密钥匙在数据目录的文件里、不在数据库里，所以只拿到数据库备份读不到原值。没有任何接口、命令和令牌能读回原值，只能整个替换。
- 保密参数的值只能是对项目密钥的引用，或触发时临时给出的值（临时值加密存在这次运行上，运行结束后删除）。运行、链实例、任务的输入里存的是引用，控制面在组装 `AssignTask` 时才解析成原值发给 Agent。新的场景版本不允许给保密参数写默认值。
- 和运行预设（ADR 0024）的关系：预设仍是场景的设置，非保密参数照旧存值；保密的预设参数改成引用项目密钥，迁移时把现有的明文值搬进项目密钥。飞书机器人的 Webhook 地址同样加密存放。项目级的非保密变量这次不做：真实使用方三个场景的 60 多个入口参数里只有 3 个是共用的，预设已经起到环境配置的作用。
- 节点代码拿到的是原值，它写进输出、日志、错误、通知里的密钥只能按值打码（现有做法），这是尽力而为，不是保证。

### 隔离做到哪一层

- **做到的**：数据和接口层。每个请求都经契约路由的检查，有从路由清单生成的跨项目测试；Agent 只属于一个项目，派发前检查。
- **还没做到的**：Agent 之间的能力端口没有认证（`agent/src/peer.rs:2`），网络上够得着的任何进程，包括别的项目的节点代码和工作台上模型的 shell，都能直接调用任何 Agent 的读文件、写文件和执行命令。给它加上凭据（控制面随任务下发短期票据，被调用方校验来自同一项目）之前，**不宣称机器层面「项目之间互相读不到」**。这一项排在 Agent 归属改造之后，是阶段 4 完成标准的一部分。在那之前靠工作台的出网名单顶住（只放行控制面和包镜像），控制面定期让工作台探测项目外 Agent 的能力端口，探得通就在项目页告警。
- 同一个项目里的会话之间不隔离；被测系统本身被两个项目的 Agent 共用时也不隔离（时钟只有一个），这两条写进文档。

### 名字从全局唯一变成项目内唯一，分两步

- **第一步**（第一次迁移就做）：节点包、飞书机器人、Agent、场景加上项目；名字仍然全局唯一，在另一个项目里重名时拒绝，提示「名字已被占用」，不说被哪个项目占用。路径已经带项目，所以第二步不再改接口。
- **第二步**：唯一约束改成「项目内唯一」；场景文档里的 Agent、节点包、飞书机器人名字按场景所在的项目解析（节点包先找本项目，再找公共项目；本项目不能发布和公共项目同名的包）；节点包在磁盘上的路径加一层项目；Agent 的身份改成「项目 + 名字」，任务上记的 Agent 名字随之带上项目。
- **第二步的触发条件**：第二个有自己的 Agent 或节点包的项目开始使用之前必须完成。它和 Agent、节点包的归属改造放在一起，排在骨架之后。

### 迁移

- 现有数据进默认项目，标准节点包的已发布版本进公共项目。
- 昵称不自动变成用户：它们没校验过，同一个人在浏览器和命令行里还可能是两个名字。历史上的昵称列保留并照旧显示，新增的用户 ID 列对旧数据留空。
- 配了 `SFLY_AGENT_TOKEN` 的部署，这个共享令牌作为默认项目的旧式凭据继续有效（任何名字都能用它连上），界面上提示逐台换成 Agent 凭据，换完后由管理员吊销。没配的部署，没有凭据的 Agent 再被接受一个版本（只限默认项目里已登记的名字，界面上告警），之后拒绝。
- 旧版命令行不带凭据，会收到 401，错误信息写明用 `sfly login`；命令行和控制面同版本安装（ADR 0012）。
- API 客户端从「写操作要昵称」变成「要令牌」，列表、新建和按名字定位的接口路径加上项目：这是不兼容变化，写进发版说明。
- 「项目」这个词留给租户。节点包在开发者机器上的那个目录改叫**节点包目录**，命令行的 `--project`（`sfly debug`、`sfly skill update`）改名 `--package-dir`，旧名保留一个版本并提示；之后 `--project` 用来选项目。

## Considered Options

- **项目从请求头取（`x-sfly-project`）**：列表、新建类接口的路径不用改。但按名字定位的资源在第二步之后要靠一个看不见的请求头才能确定是哪一个，日志、运行通知里的链接、浏览器地址都说不清指的是哪个项目，自建页面漏带请求头就会写到别的项目。
- **项目只从令牌取**：一个人在几个项目里就要几个令牌来回切，控制台的 Cookie 也没有地方放项目。
- **所有路径都带项目**（`/projects/:project/orchestrations/:id/…`）：ID 本来就确定了项目，再带一份就多出「两者不一致」这种情况，还要多改 41 个接口。
- **Agent 池共享，按项目授权**：Agent 上的文件能力不做沙箱（`agent/src/capabilities/fs.rs:3`），节点是任意 Python，共享 venv 按包名装（ADR 0002）；两个项目共用一台 Agent 时互相读得到、互相顶掉包。要补每项目的系统用户和环境，代价比装两个 Agent 大得多。
- **每个项目一个 PostgreSQL schema**：引擎的全局锁和周期扫描、指标的按天分区、迁移都要乘以项目数，Agent 那一层的问题一条没解决。
- **数据库的行级安全策略**：引擎要跨项目扫描租约和定时器，到处要开例外；检查放在契约路由一处、加上从路由清单生成的跨项目测试，更容易看全。
- **按项目签发一个注册凭据，名字随意**：装 Agent 方便，但工作台上的模型拿到它就能冒充项目里任何一台 Agent。改为按 Agent 签发。
- **每个成员按范围逐项勾选权限，不设角色**：灵活，但每加一个人都要想一遍；三种角色加平台管理员覆盖了现在的用法，角色只是范围的组合，以后好加。
- **argon2 或 bcrypt**：要原生模块，打不进单文件。scrypt 是 Node 自带的。
- **另做 CSRF 令牌**、**把跨域默认收窄成来源名单**：Cookie 只认同源请求、跨域只认令牌之后，两者都不再需要；收窄跨域会让每个自建页面都要改控制面的配置。
- **审批做成在助手一侧拦截工具调用后挂起**：拦不住（模型有 shell），挂起的状态也不该在助手进程里（#442）。
- **留一个关闭认证的开关**：两套行为都要测，「内网里先关掉」会成为常态。

## Consequences

- 一次涉及数据库、全部 HTTP 接口、Agent 注册、命令行、API 客户端和前端的改造，按任务拆分逐个合入：先加能力（表、令牌、登录、Agent 凭据、测试基建默认带凭据），最后一步才在契约路由上强制，所以中间每一步合入后测试仍然全绿。测试基建要在强制之前就能带凭据：现在 150 个控制面测试文件和 81 个 e2e 的请求都不带凭据，大部分经 `apps/server/test/support/test-control-plane.ts` 的 `fetch` 和 `api-client.ts`，少数直接请求地址，e2e 里约 24 个文件自己写了昵称请求头。
- API 客户端、命令行、自建页面都要换成令牌，列表和新建类接口的路径变了，是不兼容变化。真实使用方的离线导入要先建项目令牌。
- 助手对真实用户开放之前必须完成：身份、令牌、契约路由上的范围检查、Agent 凭据（含工作台）、会话令牌与待批准的操作、会话构建与密钥的那条规则、工作台的出网名单。成员管理、项目切换、Agent 与节点包的归属改造、项目密钥的加密存放、名字的第二步、能力端口的凭据在骨架之后。
- 场景复制到另一个项目时，文档里的 Agent、节点包、飞书机器人名字按新项目解析，可能失效；预检给出提示。
- 本地账号要自己做改密码、停用、重置；没有单点登录，以后接反向代理头或 OIDC 时用预留的外部身份列。
- 修订的其他 ADR（各自末尾加了指针）：0017「发布接口没有认证，保留前缀拦不住」与「等平台有了认证再统一处理权限」；0019「不做认证」（数据和接口层由本 ADR 处理，能力端口的凭据另做）；0020「能打开页面的人可以增删机器人」与「Webhook 明文保存」；0021「不做只读模式」与「昵称和经哪个 AI 编程助手不做校验」；0022「身份沿用昵称」与跨域的后果；0024「secret 预设参数明文保存」与「记下最后修改人的昵称」。
