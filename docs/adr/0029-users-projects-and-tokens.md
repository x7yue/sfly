# 项目是顶层租户；人用本地账号登录，程序用令牌；权限只在契约路由一处检查

ADR 0004 的前提是「平台只在内网、每个人有自己的测试环境」，所以身份只是不校验的昵称。这个前提已经不成立：平台里要加入助手（#442），模型有 shell，能绕开任何界面直接请求 HTTP 接口，能拦住它的只有控制面上它够不着的检查；平台也要能让几个团队共用一套控制面而互相看不到。所以平台建模**用户**和**项目**：项目是顶层租户，场景、运行、节点包、飞书机器人、Agent、会话和工作台都属于一个项目；人在控制台用本地账号登录，命令行、API 客户端、Agent 和助手会话都用令牌；每个接口要什么身份、作用在哪个项目上，只在契约路由一处检查。认证默认开启，不留关闭的开关。

本 ADR 修订 ADR 0004 里「不建模用户」的一半。另一半照旧成立：平台不建模测试环境，不做资源锁和 Agent 自动选择，场景里直接写 Agent 的名字，换环境就复制场景。

## 规则

### 用户、项目与角色

- **用户**是本地账号（登录名、显示名、密码哈希、是否停用），表里留一列外部身份，以后接反向代理头或 OIDC 时不用再迁移。用户被停用时，他的登录、令牌和他发起的会话全部立即失效。
- **平台管理员**是用户上的标记：建项目、管理账号、维护公共项目，并在每个项目里拥有项目管理员的权限（项目最后一位项目管理员离开时靠它恢复）。这是「另一个项目读不到」的例外，拦不住（他本来就能登录主机、重置任何人的密码），但要对项目透明：平台管理员在自己不是成员的项目里做的写操作都留下记录（谁、什么时候、调用了什么、作用在哪个资源上），项目的成员看得到。
- **项目**有不可修改的标识（小写字母、数字、连字符，出现在路径里）和可以修改的显示名。迁移时建两个：**默认项目** `default`，现有的数据全部归它；**公共项目** `public`，放平台维护的节点包（标准节点包，#454），任何凭据都能读、任何项目的场景都能引用，只有平台管理员能发布。
- **成员**指用户在一个项目里的身份，每个成员有一种**角色**：**只读**、**编辑者**、**项目管理员**。角色是固定的一组范围（下表），检查只看范围，不看角色名；以后要加「只能触发运行」这类角色，只是多一组范围。
- 一台机器要给两个项目用，就装两个 Agent（不同的系统用户、`SFLY_HOME`、名字和端口），隔离交给操作系统。

| 范围 | 允许什么 | 只读 | 编辑者 | 项目管理员 | 会话令牌 |
|---|---|---|---|---|---|
| 读 | 项目内一切只读接口（密钥的原值没有接口） | ✓ | ✓ | ✓ | ✓ |
| 运行 | 触发、取消运行 | | ✓ | ✓ | ✓（限勾选的 Agent、取消限自己触发的运行） |
| 编辑 | 场景、场景版本、场景的设置（运行通知、关注项、运行预设）的增改与归档 | | ✓ | ✓ | ✓（限会话自己建的和勾选的场景） |
| 会话构建 | 登记会话构建 | | ✓ | ✓ | ✓（限自己的会话） |
| 发布 | 发布节点包的正式版本 | | ✓ | ✓ | 要人批准 |
| 管理 | 成员、项目令牌、Agent 与它的凭据、飞书机器人、项目密钥、Agent 立即更新 | | | ✓ | 不能 |

### 凭据

| 凭据 | 谁用 | 属于 | 怎么带 | 有效期 |
|---|---|---|---|---|
| 登录 Cookie | 控制台 | 用户 | HttpOnly、SameSite=Lax 的 Cookie | 空闲超时，可注销自己全部的登录 |
| 个人令牌 | 命令行、API 客户端、自建页面 | 用户，可限定一个项目和一部分范围 | `Authorization: Bearer` | 可设过期，可吊销 |
| 项目令牌 | 自动化、自建页面 | 项目（服务账号），选定范围 | 同上 | 同上 |
| 会话令牌 | 工作台上的 `sfly` | 一个会话：代发起人、限一个项目 | 同上 | 随会话结束；停止会话就是吊销它 |
| Agent 凭据 | Agent | 一台 Agent（项目 + 名字固定） | gRPC `Hello.token`；Agent 请求 HTTP 时 `Bearer` | 可吊销、可轮换 |
| 任务凭据 | 任务里的 SDK（下载产物） | 一次任务尝试 | 随 `AssignTask` 下发，只对控制面的地址带 | 任务结束即失效 |

- 令牌都是高熵随机串，带种类前缀（例如 `sfly_pat_`、`sfly_ses_`、`sfly_agt_`），便于识别和在日志里打码；库里只存 SHA-256 哈希，原值只在签发时显示一次。
- **权限取交集**：个人令牌和会话令牌每次请求都取「令牌的范围」和「用户（会话的发起人）此刻在该项目的角色」的交集。用户被降级、移出项目或停用，他的令牌和会话随之失去权限。
- **个人令牌是用户自己的资源**，不属于项目，不走项目的范围表（范围表里的「令牌」只指项目令牌）。账号类接口定位在当前用户自己（资源类别 `account`，`target: "self"`），路径不带项目，各认哪种凭据如下（没列的凭据一律不认）。只读角色和编辑者都能签自己的个人令牌；签出的令牌范围不超过签发人此刻的角色。

  | 接口 | 认哪种凭据 |
  |---|---|
  | 登录、初始化第一个管理员 | 不要凭据（初始化要初始化码） |
  | 注销登录 | 登录 Cookie |
  | 改密码 | 登录 Cookie，加上旧密码 |
  | 签发个人令牌 | 登录 Cookie，或账号密码（`sfly login`）；令牌不能签发令牌 |
  | 吊销个人令牌 | 登录 Cookie 可以吊销自己的任何一个；个人令牌只能吊销它自己（`sfly logout` 用） |
  | 列出自己的令牌 | 登录 Cookie 或个人令牌（只列名字、前缀、范围、最后使用时间） |
- **Agent 凭据由项目管理员签发**（Agent × 写 →「管理」），开发 Agent 除外。开发 Agent 走一个独立的接口（「我的开发 Agent」，资源类别 `dev_agent`，在项目下新建）：名字由控制面生成，统一是 `dev-<登录名>-<主机>`：登录名的字符集不含连字符（小写字母、数字、下划线，有长度上限），所以 `dev-` 之后到下一个连字符之前就是登录名，它来自凭据，冒用不了别人的；主机那一段由请求给出，限定字符集和长度，整个名字有总长上限；同一个人在同一个项目里重名时拒绝，提示换一个主机名。名字里不带项目：开放建项目排在名字改成项目内唯一之后（见「名字从全局唯一变成项目内唯一」），第一步期间只有默认项目，第二步之后名字本来就按项目唯一；查表是 `dev_agent` × 写 →「编辑」，并且只认有用户的人的凭据（Cookie、个人令牌），会话令牌和项目令牌都不行。凭据记在这个用户名下，只有他自己和项目管理员能吊销。由此编辑者可以让场景里带保密参数的节点跑在自己的开发机上；编辑者本来就能写拿到密钥的节点代码，这不是新的口子。
- **工作台的 Agent 用自己的 Agent 凭据**（骨架阶段就做），共享令牌不发给工作台：模型的命令读得到工作台上的凭据，按 Agent 签发的凭据只能冒充这一台工作台。
- 「经 …」（`triggered_via`、`author_via`）记两样：令牌（会话令牌记会话，其余记令牌的名称），以及 `x-sfly-client` 里的 AI 编程助手名。前者是可信的，后者仍是不经校验的标注，用来保留现在的「经 Claude Code」。

### 项目从请求的哪里来

项目不从请求头取，也不只从令牌取：按资源怎么定位分四类（现有 74 个路由，按路由清单 `sdk/python/src/sfly/schemas/routes.json` 分）。

| 类 | 路由 | 项目怎么得出 | 数量 |
|---|---|---|---|
| 路径带项目 | 列表与新建（场景、运行、Agent、节点包、飞书机器人、控制台统计），以及按名字定位的 Agent、节点包、飞书机器人 | 路径改成 `/projects/:project/…` | 18 |
| 经场景 | `/orchestrations/:id/…`（版本、设置、预设、预检、触发） | 场景所在的项目 | 21 |
| 经运行或任务 | `/runs/:id/…`、`/tasks/:id/…`（详情、取消、日志、指标、动作、产物） | 运行所在的项目（`runs` 冗余一列 `project_id`） | 20 |
| 不属于项目 | 健康检查、文档、SDK 与 Agent 二进制、安装脚本、API 客户端安装包、Python 索引 | 不需要凭据 | 15 |

- 和 #448 的声明对得上，不另加「项目来自哪」的声明，靠一条由契约测试检查的约定：`target` 是 `collection`、`upload`，或者用名字定位（Agent、节点包、飞书机器人），路径里必须有 `:project`；用 ID 定位的（场景、运行、任务，以及以后的会话）路径里不能有 `:project`，项目从资源得出；`system` 两者都没有。 成员、项目令牌、项目密钥归到一个资源类别 `project`（它们是项目的一部分，和「运行预设是场景的一部分」同一条规则），用路径里的 `:project` 定位项目本身（`target: { params: "project" }`），和这条约定一致。公开路由 `/simple/:project/` 的参数指 PEP 503 里的包，改名 `:package`，免得和约定混淆。
- 凭据本身限定了项目的（项目令牌、会话令牌、Agent 凭据、任务凭据，以及限定项目的个人令牌），和请求得出的项目不一致就拒绝；有用户的凭据（登录 Cookie、个人令牌、会话令牌）都还要看用户此刻的角色（见「权限取交集」）；项目令牌、Agent 凭据、任务凭据没有用户，只看自己的范围。
- 资源不存在、属于别的项目、凭据限定的项目不是这个，一律返回 404，不泄露别的项目有什么；403 只用于「在这个项目里，但没有这个范围」。公共项目例外：任何凭据都能读它，限定了项目的令牌读标准节点包的详情照常得到结果。
- 公开路由里 `/health` 和 `/sdk/project-settings` 会暴露版本号和镜像地址：安装 Agent 和 `sfly init` 要用到，可以接受。
- **SSE**：事件流本来就是契约里的路由、经同一个注册入口（`contract-route.ts:124`），订阅时做同样的检查；控制台和 API 客户端用 `fetch` 读事件流（`packages/client/src/subscribe.ts:79`），能带 `Authorization`。凭据被吊销、用户被停用或移出项目、登录被注销时，控制面关掉受影响的事件流（单进程，按凭据和用户登记即可）。
- **Agent 的 gRPC 流**：身份在 `Hello` 时从 `token` 得出，`Hello.name` 必须和凭据上的名字一致；之后这条流上的消息都以这台 Agent 的身份处理，只接受派给它的任务的上报。协议不加字段。

### 一处检查

- **范围不逐个接口手写**，由 #448 给每个接口的声明查一张表得出。声明有 `effect`（`read` 或 `write`）、`resource: { kind, target }`（定位到哪类资源的哪一个），以及两个可选项：`creates`（新建的是哪类资源）、`removes`（删除或归档定位到的资源）。规则：**范围由「接口作用在哪类资源上 × 只读或写」查表得出，「作用在哪类资源上」取 `creates`（有的话），否则取 `resource.kind`；项目的检查始终用 `resource` 定位到的那个资源。**写了 `creates` 的接口，定位到的资源只被读，所以会话勾选范围（它约束的是会话能写什么）不查定位到的资源；新建出来的资源属于会话。
- 范围表，以及按这条规则过一遍现有接口的结果：

  | 接口（声明） | 查表用的类别 × 读写 | 范围 | 项目和勾选按哪个资源查 |
  |---|---|---|---|
  | 所有只读接口 | 任意 × 读 | 读 | 定位到的资源 |
  | 保存版本、恢复版本、改设置（运行通知、关注项）、新建、归档与恢复场景（场景，写） | 场景 × 写 | 编辑 | 定位到的场景；新建按路径里的项目 |
  | 复制场景（场景，写，`creates: scenario`，定位到源场景） | 场景 × 写 | 编辑 | 源场景只被读：要能读它、在它的项目里有「编辑」；会话不需要勾选源场景，副本属于会话 |
  | 运行预设的增改、复制、删除（场景，写） | 场景 × 写 | 编辑 | 定位到的场景 |
  | 触发运行（场景，写，`creates: run`） | 运行 × 写 | 运行 | 场景只被读，会话不需要勾选它；用到的 Agent 要在勾选里，由触发准入查 |
  | 取消运行（运行，写） | 运行 × 写 | 运行 | 定位到的运行；会话只能取消自己触发的 |
  | 登记会话构建（会话，写，`creates: session_build`） | 会话构建 × 写 | 会话构建 | 定位到的会话：只能是令牌自己的会话 |
  | 发布正式版本（节点包，写，`upload`） | 节点包 × 写 | 发布 | 路径里的项目 |
  | Agent 立即更新、停用和恢复 Agent、飞书机器人的增删改与测试消息（写） | Agent、飞书机器人 × 写 | 管理 | 定位到的资源 |
  | 成员、项目令牌、项目密钥的写（`project`，写，随各自的任务加入） | 项目 × 写 | 管理 | 路径里的项目 |
  | 我的开发 Agent：新建、吊销（`dev_agent`，写） | 开发 Agent × 写 | 编辑；只认有用户的人的凭据，会话令牌不行 | 路径里的项目；吊销时要是自己的，或有「管理」 |
  | 账号类接口：登录、改密码、个人令牌（`account`，`target: "self"`） | 不查项目的范围表 | 登录和初始化不要凭据；其余只认人的登录 | 不属于项目 |
  | 上传产物（任务，写） | 任务 × 写 | 不给人和程序：只有 Agent 凭据，限派给这台 Agent 的任务 | 定位到的任务 |

- **Agent 凭据和任务凭据不走范围表**，各有一份显式的接口清单，清单之外一律拒绝；清单和范围表放在同一处检查里。Agent 凭据：下载节点包归档（本项目和公共项目的包）、上传产物（派给这台 Agent 的任务）。任务凭据：下载产物（`GET /tasks/:id/artifacts/*`，本项目的任务），这是任务里的 SDK 唯一发的请求（`sdk/python/src/sfly/download.py:129`）；上传产物由 Agent 在任务结束后做，用的是 Agent 凭据。任务凭据在任何节点代码里都拿得到，所以不给它「任务的读」那样宽的范围（那会包括全项目每个任务的日志和动作）；节点要读这次运行的状态，走派发时解析的输入（#452 的 `${{ run.state }}`），不经接口。共享令牌不对应任何一台 Agent：带共享令牌的 HTTP 请求和不带凭据的走同一套过渡放行（见「迁移与过渡」，只看 URL 里的任务或版本）。
- **会话构建和正式版本走两个接口**：正式版本是项目下的节点包上传，要「发布」，拒绝带会话标签的版本号；会话构建登记在会话下，要「会话构建」，会话标签由控制面给，「只被本会话引用、会话结束回收」这些规则放在会话构建这类资源上。不用同一个接口加参数或按版本号区分：现在的版本号规则本来就允许带 `+` 的本地标签（`packages/schema/src/package-metadata.ts:180`），那样范围要看请求体甚至上传内容才能定，鉴权就不再是只看声明的一处检查。会话要发正式版本，就用会话令牌调正式版本的上传：它没有「发布」范围，这个请求（连同上传的归档）变成待批准的操作。
- **所有 GET 都没有副作用**：契约测试要求 GET 接口声明 `effect: "read"`（#448 的只读测试核对它真的不写库）。下文的跨站规则依赖这一条。
- 检查放在契约路由的注册入口：解析凭据、按声明得出项目、查归属、查范围、查会话的勾选，全部通过才进处理函数；Fastify 为 GET 自动生成的 HEAD 路由走同一处。现在散在各路由里的 `requireNickname` / `requireActor`（18 处）删掉。启动守卫（`contract-route.ts:180`）同样拒绝缺声明的接口。平台管理员在非成员项目里的写操作，记录也在这一处写。
- 只有一处例外：场景文档按名字引用的 Agent、节点包、飞书机器人不在接口的 `resource` 里，要解析文档才知道。保存版本和触发运行时检查它们都属于场景所在的项目或公共项目：保存时警告，触发时阻断，和现有的预检走同一条路（名字全局唯一的第一步期间，不这样做就能让平台往别的项目的群里发消息）。触发运行时用到哪些 Agent、哪些任务带保密参数，同样由触发准入判断（预检和派发用同一个判断），它从请求拿到同一份凭据上下文。
- 有一组从路由清单生成的测试：项目甲的每种凭据访问项目乙的每个接口都被拒绝，每个接口一条，新加的接口自动覆盖。

### 助手会话

- 建会话时，人勾选三样：可以改的场景、可以用的 Agent、可以发消息的飞书机器人，以及是否「联调时可以使用项目密钥」，控制面签发会话令牌。会话自己建的场景（联调副本）、会话构建、触发的运行记着属于哪个会话；联调副本不再按昵称命名，按会话和用户区分。
- 默认直接做：读项目内的东西；复制项目内任何场景得到联调副本（复制是对源场景的读，副本属于会话）；改会话自己建的和勾选的场景；触发项目内的场景，但只用勾选的 Agent；登记会话构建；取消自己触发的运行。复制和触发都不需要勾选场景：会话能复制就能触发自己的副本，再要求勾选原场景只会逼人把改原场景的权利一起给出去。会话「默认只改自己的联调副本」（#442）由此成立。「可以用的 Agent」在触发时定下、记在运行上，这次运行之后派发的任务（包括中途创建的子流程）都按它检查；它只管任务派到哪里，在能力端口有凭据（见「隔离做到哪一层」）之前，管不住节点经能力端口去调用没勾选的 Agent。
- **会话触发的运行只往勾选了的机器人发消息**：运行通知和节点里的 `ctx.notify` 同一条规则，在消息进入发送队列时按会话此刻的勾选判断；没勾选的不入队，在任务日志或运行详情里留一行说明（投递本来就不影响任何状态，ADR 0020）。这是机器人项目归属之上的第二层：先要和场景同一个项目，再要在会话的勾选里。会话已结束、运行还在跑时，按会话结束那一刻的勾选。发起人此刻在这个项目里没有「运行」范围（被降级、移出、停用）时一律不发，不管会话结没结束。已经入队的消息照常投递，事后取消勾选只影响之后入队的。 飞书通知节点（引擎直接把消息放进队列）不在这条规则里：它由 #445 的第 1 项删除，那一项和第 4 项（在线编辑者）一样是开放之前的条件。
- 会话（`session`）和会话构建（`session_build`）两个资源类别随骨架加进 `RESOURCE_KINDS`。会话令牌对会话这一类只有读：不能建会话，也不能批准自己的待批准的操作。
- **越权的写请求变成待批准的操作**：会话令牌的写请求没通过勾选或范围检查、属于可以批准的几种、并且发起人此刻自己有权做时，控制面不返回 403，而是把这个请求（方法、路径、请求体、会话、发起人）存成一条**待批准的操作**，返回 202。契约里 202 是统一的响应形状（操作 ID 和「等人批准」的说明），命令行统一处理：打印操作 ID，用专门的退出码。
  - 可以批准的只有：发布正式版本；改动勾选范围以外的场景；用没勾选的 Agent；取消别人的运行。
  - 批准时再查一次：发起人此刻仍有权做这件事，批准人自己也有这项权限，否则在批准这一步拒绝或作废。
  - 批准后控制面把原请求重新走一遍同一条路由（乐观锁、预检照常生效），结果记在这条操作上。由此产生的记录，「谁」记批准人，「经」记会话；成果清单按「经」列全。
  - 同一个会话重复提交完全相同的越权请求，返回同一条待批准的操作；每个会话待批准的数量有上限，超过就拒绝。
  - 拒绝、会话结束都让它失效。它是数据库里的对象，控制面重启不丢。
- 不能做、也不能批准：管理范围的一切；删除或归档不是会话自己建的东西（声明了 `removes` 的接口）；读密钥的原值。
- 会话失去权限（发起人被降级、移出、停用，或会话结束）之后，它已经触发的运行照常跑完，会话不能再取消它们。
- **会话令牌触发的运行，保密参数默认都不解析**：不论值是对项目密钥的引用、场景版本里内嵌的默认值，还是运行预设里存的值（项目密钥做出来之前后两种是直接存着的，复制场景会把它们一起带进副本），一律当作没有提供：缺了必填的保密参数，触发被拒绝，原因写明怎么放行；可选的保密参数，节点拿到的是 `null`，因此在派发时报类型不符的，错误信息写明原因是「会话触发的运行不解析保密参数」。会话在触发请求里自己给出的值照常使用（那是它本来就知道的值，不是项目的密钥），仍按保密参数打码。不管用没用会话构建都是这样；建会话时人勾选了「联调时可以使用项目密钥」才放行。是否放行在触发时定下、记在运行上，之后改勾选只影响新的运行。理由：会话能复制任何场景、用任意已发布的节点把参数打印出来，也能用会话构建写任意代码，拿到原值就能带出去，按值打码拦不住。所以「定位到的资源只被读」要说准：复制带进副本的保密值，会话读不到（接口打码，#467），也用不了（它触发的运行不解析）；节点输出里的原值也一样，只在这次运行内部传给下游（见「密钥」的原样输出）。
- **带保密参数的任务不派到工作台**（任务的输入里引用了保密参数，包括经子流程参数传进去的；或者引用了含原值的上游输出，即原样输出和打码后的那份不一样），除非这次运行是勾选了上一条的会话触发的，并且这台工作台属于这个会话的项目。人触发的运行、没勾选的会话的运行，目标 Agent 是工作台且带保密参数时，预检阻断并写明原因；含原值的上游输出要到派发时才知道，这种情况派发拒绝，任务以配置错误失败并写明原因。理由：派到哪台 Agent，原值就落在哪台的 `task.json` 里，工作台上模型的 shell 读得到。
- 人触发一个会话改过的场景时，用的是人的身份，密钥照常解析，而节点可能是会话改的或写的。这算「人审过场景再运行」，不在上面两条之内；成果清单和版本对比要让人看清会话改了什么。
- **谁正在改这个场景**：取代现在的在线编辑者（#445 删除它，#442 定了取代的做法）。它由平台自己知道的事实算出，不需要心跳，也不认请求里给的任何标识：有未结束的会话能写这个场景（场景是它建的，或在它的勾选里），以及最近一次保存的人和时间（经会话保存的标明是哪个会话）。人只是在画布上打开、还没保存时不算：并发修改的正确性本来就由场景版本的乐观锁保证，提示只为人和助手之间的冲突，而这部分平台从会话的勾选就知道。
- 现有的在线编辑者接口在删除之前有一个已知问题：任何有读权限的调用方都能用别人的会话标识让别人从「谁在编辑」里消失（`apps/server/src/presence/presence-registry.ts:44`、`:65`）。#445 删除它们是多用户开放之前必须完成的一项，不为它们设计身份绑定。

### 认证的几处细节

- **第一个管理员**：控制面启动时没有任何用户，就在日志里打印一次性的初始化码（同时写进数据目录里一个只有属主可读的文件），用它在 `/setup` 页建第一个平台管理员；自动化部署和测试可以改用环境变量给出初始管理员。离线安装不依赖邮件。管理员忘了密码，在控制面所在的主机上执行重置命令（能登录主机就已经是最高权限）。
- **密码**用 Node 自带的 `crypto.scrypt` 存哈希，参数和盐写进存储串，以后可以平滑调高；控制面是 esbuild 打的单文件（`apps/server/scripts/bundle.ts`），不能引入 argon2、bcrypt 这类原生模块。登录按用户和来源地址限速。
- **跨站请求**：只对两类带 Cookie 的请求做来源检查，检查不过就当作没有登录：有副作用的方法（非 GET、HEAD），以及不是页面导航的跨站请求。导航（例如从飞书卡片、别的内网站点点开日志或产物的下载链接）照常带着登录。判断时优先看 `Sec-Fetch-Site`：`same-origin` 和 `none` 放行；没有它时看 `Origin`，和配置的公开地址（`SFLY_PUBLIC_URL`，反向代理后面就是浏览器看到的地址）比较；开发时 vite 代理把请求转给控制面，开发配置把 vite 的地址也算作同源。两个头都缺的有副作用请求当作跨站。不另做 CSRF 令牌；SameSite 不够用，同一个公司域名下的其他内网站点算「同站」。
- **跨域的默认值不变**，仍允许所有来源，但永远不发 `Access-Control-Allow-Credentials`：跨域只能用请求头里的令牌，没有令牌的请求一律 401，所以「内网任何网页都能触发运行」（ADR 0022 的后果）随之消失，自建页面换上项目令牌就能继续用。CORS 允许的请求头要加上 `authorization`（现在没有：`apps/server/src/http/cors.ts:11-16`）。

### 密钥

- **长期存放的原值只在一处**：项目的**密钥**表，加密存放，加密钥匙在数据目录的文件里、不在数据库里，所以只拿到数据库备份读不到原值。没有任何接口、命令和令牌能读回原值，只能整个替换。
- 保密参数的值只能是对项目密钥的引用，或触发时临时给出的值。运行、链实例、任务的输入里存的是引用（临时值存进运行的加密副本，见下）；控制面在组装 `AssignTask` 时才解析成原值发给 Agent。新的场景版本不允许给保密参数写默认值。
- **写入时打码**：凡是这次运行写进库的值，都用这次运行的**原值集合**打码后再存，读取时不再依赖原值。它覆盖两类：
  - Agent 上报的内容：日志、输出、错误、动作、进度、通知内容。
  - 控制面自己解析后写进库的每一处：运行的参数（`runs.params`）、链实例的参数（`chain_instances.params`，异步任务节点按映射传进子流程的值）、任务的输入（`tasks.inputs`，从参数和上游输出解析出来的）、控制面自己生成的错误信息（`tasks.error_message`，例如派发时报类型不符时引用的值）、飞书发送队列的消息体（`feishu_messages.body`）。
  - 派发给 Agent 的仍是原值，库里只存打码后的。派发、重试、中途创建的子流程需要的原值，从这次运行加密存放的那一份（见下面的「运行的加密副本」）重新解析，不从库里打码后的列读。发到飞书群里的消息就是存下的那份，所以也是打码后的。
  - 现在日志和动作已经在写入时打码，但只认得写入那一刻已有的链实例里的参数值（`apps/server/src/logs/task-logs.ts:339`、`:368`），其余在读取时才打码（`apps/server/src/runs/run-read.ts:351`）；参数改成引用、密钥可以替换之后，读取时就没有原值可以对照了，所以全部改到写入时。写入时打码先于项目密钥做（属于助手开放之前）。
- **运行的加密副本**：按运行一份，控制面在内存里持有，同时加密落在运行上，重启后从那里恢复。它包括三样：
  - **原值集合**：这次运行实际解析出的全部原值，用来打码。按运行一份（不按任务），同一次运行里任何任务的上报和写进库的值都按它打码。重试按引用重新解析：运行中途密钥被替换，重试拿到新值，新值也加进集合。
  - **参数的原值**：运行和链实例的保密参数的原值（项目密钥做出来之前，就是触发时的值；之后是触发时临时给出的值，引用则在派发时解析）。
  - **原样输出**：节点的输出原样传给下游，这是平台对节点作者的承诺（`docs/SEMANTICS.md`），不因打码改变。引擎另存一份原样的输出，只给下游节点解析输入用；读取、展示、接口、命令行、通知一律用打码后的那份。节点读这次运行的状态（#452 的 `${{ run.state }}`，派发时解析）读的是打码后的一侧，不含任何输出，和原样输出没有交集；只引用它的节点不算带保密参数。
- **什么时候删除**：运行的加密副本在「运行已结束，并且它的每次尝试都已离开 Agent 之手」之后删除。一次尝试离开 Agent 之手，是指它的结果已被控制面 Ack，或者控制面已在 Welcome 里告诉 Agent 放弃它、且这台 Agent 之后的心跳里不再列出它（Agent 的任务台账，`agent/src/ledger.rs`）。租约过期不算：那正是 Agent 之后可能重连补报的情况。Agent 永远不回来时，以运行结束后的日志保留期为上限。
  - **删除之后迟到的上报一律丢弃**，不存，按运行记下丢了多少条、原因是什么，运行详情里看得到。被放弃的尝试在断线期间排队的日志，可能在心跳不再列出它之后才到，同样丢弃并计数。
- Agent 本地的日志副本和 `task.json` 不打码：它们在 Agent 机器上，边界是那台机器。按值打码是尽力而为：节点把原值变形、编码之后就认不出了。
- **写入时打码之前的运行**照旧在读取时打码：运行上记一个标记，表示它是不是在写入时打的码；没有标记的运行，参数里原值还在，读取时打码照样能做，等迁移（见「迁移与过渡」）处理完它再关掉。
- 这些规则在异常时序下的行为：

  | 情况 | 运行的加密副本 | 写进库的值、上报、消息 |
  |---|---|---|
  | 控制面重启 | 从运行上的加密副本恢复 | 重启后重新解析的任务输入、链实例参数从副本取原值，写进库的照常是打码后的；上报照常打码 |
  | 重试 | 按引用重新解析，拿到的新值加进原值集合 | 重试任务的输入从副本解析，写进库的是打码后的 |
  | 子流程在运行中途创建 | 它的参数从副本里的参数原值和原样输出解析，新出现的原值加进集合 | 链实例参数和它的任务输入写进库的是打码后的 |
  | Agent 离线很久后重连补报 | 尝试还没离开它的手，副本保留 | 照常打码存下 |
  | 运行被取消时 Agent 不在线 | 运行结束了，但尝试还在 Agent 手上，副本保留到 Agent 回来被告知放弃、心跳不再列出它，或到上限 | 期间照常打码；之后丢弃并计数 |
  | 任务被判 `agent_lost`、重试之后旧尝试又报上来 | 旧尝试在 Agent 重连的 Welcome 里被放弃；离手之前副本保留 | 离手之前照常打码存下；之后（包括断线期间排队、离手后才到的日志）丢弃并计数 |
  | Agent 永远不回来 | 运行结束后过了日志保留期删除 | 之后到达的丢弃并计数 |
  | 重试拿到替换后的密钥 | 新旧两个值都在集合里 | 两个值都打码 |
  | 会话触发运行之后，「可以使用项目密钥」被改 | 放行与否在触发时记在运行上，这次运行的重试和子流程照旧；新的运行按新的勾选 | — |
  | 会话触发运行之后，Agent 的勾选被改 | 可以用的 Agent 在触发时记在运行上，这次运行之后的派发（含中途创建的子流程）照旧按它；新的运行按新的勾选 | — |
  | 会话触发运行之后，机器人的勾选被改 | — | 消息按入队那一刻的勾选：取消勾选之后入队的不发，加上勾选之后入队的照发；已入队的照常投递 |
  | 会话结束了，它触发的运行还在跑 | — | 按会话结束那一刻的勾选发；发起人此刻没有「运行」范围时不发 |
  | 发起人被降级或移出项目，会话还没结束 | — | 发起人此刻没有「运行」范围，一律不发 |
  | 重试时机器人已被取消勾选 | — | 重试里 `ctx.notify` 入队时判断，不发；运行结束的运行通知同理 |
  | 可选的保密参数在会话触发的运行里没解析 | — | 节点拿到 `null`；派发时报类型不符的，错误信息写明原因（写进库的错误信息同样打码） |
- 和运行预设（ADR 0024）的关系：预设仍是场景的设置，非保密参数照旧存值；保密的预设参数改成引用项目密钥。飞书机器人的 Webhook 地址同样加密存放。项目级的非保密变量这次不做：真实使用方三个场景的 60 多个入口参数里只有 3 个是共用的，预设已经起到环境配置的作用。

### 隔离做到哪一层

- **做到的**：数据和接口层。每个请求都经契约路由的检查，有从路由清单生成的跨项目测试；Agent 只属于一个项目，派发前检查。
- **还没做到的**：Agent 之间的能力端口没有认证（`agent/src/peer.rs:2`），网络上够得着的任何进程，包括别的项目的节点代码和工作台上模型的 shell，都能直接调用任何 Agent 的读文件、写文件和执行命令。给它加上凭据（控制面随任务下发短期票据，被调用方校验来自同一项目）之前，**不宣称机器层面「项目之间互相读不到」**。这一项排在 Agent 归属改造之后，是阶段 4 完成标准的一部分。在那之前靠工作台的出网名单顶住（只放行控制面和包镜像），控制面定期让工作台探测项目外 Agent 的能力端口，探得通就在项目页告警。
- 同一个项目里的会话之间不隔离；被测系统本身被两个项目的 Agent 共用时也不隔离（时钟只有一个），这两条写进文档。

### 名字从全局唯一变成项目内唯一，分两步

- **第一步**（第一次迁移就做）：节点包、飞书机器人、Agent 加上项目，名字仍然全局唯一。场景不在其中：场景的名字现在就不唯一，库里没有约束。在另一个项目里重名时拒绝，提示「名字已被占用」：这会泄露别的项目里存在这个名字，第一步期间接受它，因为这段时间实际只有默认项目和公共项目。路径已经带项目，所以第二步不再改接口。
- **第二步**：唯一约束改成「项目内唯一」；场景文档里的 Agent、节点包、飞书机器人名字按场景所在的项目解析（节点包先找本项目，再找公共项目；本项目不能发布和公共项目同名的包）；节点包在磁盘上的路径加一层项目；Agent 的身份改成「项目 + 名字」。运行视图、Agent 页、控制台里的 `agent` 字段仍是纯名字，项目由运行得出。
- **第二步的触发条件**：第二个项目开始建任何带名字的资源（Agent、节点包、飞书机器人）之前必须完成。所以开放建项目要等第二步完成，第一步的泄露只存在于只有默认项目和公共项目的这段时间。它和 Agent、节点包的归属改造放在一起，排在骨架之后。

### 迁移与过渡

- 现有数据进默认项目，标准节点包的已发布版本进公共项目。
- 昵称不自动变成用户：它们没校验过，同一个人在浏览器和命令行里还可能是两个名字。历史上的昵称列保留并照旧显示，新增的用户 ID 列对旧数据留空。
- **Agent 的过渡**（ADR 0014 要求相邻版本兼容）：
  - 配了 `SFLY_AGENT_TOKEN` 的部署，这个共享令牌作为默认项目的旧式 Agent 凭据登记进库，继续有效（任何名字都能用它连上），界面上提示逐台换成 Agent 凭据，换完后由管理员吊销。
  - 不带凭据的 Agent 再被接受一个版本，只限默认项目里已登记的名字，界面上告警。下文的「以旧方式连接」指不带凭据或用共享令牌连接。
  - 同名的新连接顶掉旧连接（`apps/server/src/agents/agent-hub.ts:225-242`）是为了让断电、断网后重启的 Agent 马上连得上（服务端那条死掉的旧连接要等传输层发现才结束），这一点保留：以旧方式连接的之间照旧可以互相顶掉；只有一条例外，以旧方式连接的不能顶掉带 Agent 凭据的连接。
  - 登记工作台之前，部署里没有停用的 Agent 必须都已经换成 Agent 凭据：登记这一步检查，有没换的就拒绝并列出它们。登记之后，控制面既不接受不带凭据的 Agent，也不再接受共享令牌（共享令牌不发给工作台，但工作台在网络上够得着控制面，模型拿到别处泄露的共享令牌就能冒充一台还没换凭据的 Agent）。这是骨架的前置条件。
  - 为此加一个「停用这台 Agent」的操作（项目管理员，Agent 的写 →「管理」）：停用的 Agent 不能连接、不参与派发（预检阻断并写明原因）、不计入上一条检查，可以恢复。现在没有删除 Agent 的接口，早就下线的旧记录否则会让工作台永远登记不了；它本来也是缺的管理功能。
  - 同一个窗口期覆盖旧 Agent 和旧 SDK 的三条 HTTP 通道：不带凭据的下载节点包归档，只对「派给某台以旧方式连接的 Agent、还没结束的任务要用的那个版本」放行；不带凭据的上传产物，只对派给这样一台 Agent、还在上报期内的任务放行；任务里旧 SDK 不带凭据的下载产物，只对「有任务正在这样一台 Agent 上执行」的运行的产物放行。否则升级控制面那一刻，旧 Agent 正在排空的任务装不了包、传不了产物（上传失败会把成功的任务改成失败）。代价：窗口期内，知道某个任务 ID 的人能不带凭据下载那次运行的产物；任务 ID 只有项目成员看得到。
- 旧版命令行不带凭据，会收到 401，错误信息写明用 `sfly login`；命令行和控制面同版本发布（ADR 0010、0021）。
- API 客户端从「写操作要昵称」变成「要令牌」，列表、新建和按名字定位的接口路径加上项目：这是不兼容变化，写进发版说明。
- 「项目」这个词留给租户。节点包在开发者机器上的那个目录改叫**节点包目录**，命令行的 `--project`（`sfly debug`、`sfly skill update`）改名 `--package-dir`，旧名保留一个版本并提示；之后 `--project` 用来选项目。其余旧用法一并改名：`/sdk/project-settings` 里的「项目」指节点包目录；文档里把 Agent 的共享注册令牌叫「令牌」的地方改叫「共享令牌」或「Agent 凭据」。
- **已有的明文密钥**（在项目密钥做出来时一并迁移）：
  - 运行预设里保密参数的值搬进项目密钥，预设改成引用。飞书机器人的 Webhook 地址原地加密。
  - 场景版本里保密参数的默认值：搬进项目密钥，版本文档里的值替换成对它的引用。这是对不可变版本的一次性改写，本 ADR 明文允许，只此一次：引用解析出来的值和原来相同，执行结果不变；而保留在版本里就意味着原值永远留在数据库和它的备份里，「长期只在一处」不成立。接口上的打码由 #467 先做。
  - 历史运行（`runs.params`、`chain_instances.params`、`tasks.inputs`）：只处理「运行已结束、并且每次尝试都已离开 Agent 之手」的运行（和原值集合的删除条件同一个判断）；迁移开始时还在跑的运行，等它满足这个条件再处理，免得一边追加日志一边重写，或者让重试、中途创建的子流程解析到占位符。处理一个运行时，先用它自己的原值对库里的输出、错误、动作、进度、通知内容做一次写入式打码；日志和动作现在本来就在写入时打码（`task-logs.ts:339`、`:368`），只漏掉子流程创建之前写下的、含子流程保密参数的行，所以只重写这类运行的日志文件（核实过：每批写入都按当时已有的链实例取值）。做完之后把参数里的保密值原地替换成占位符，并给运行打上「已在写入时打码」的标记，关掉它的读取时打码。中途重启从没做完的运行继续，在后台做、不阻塞启动。代价是对每个历史任务的几列做一次库内更新，加上少数运行的日志重写。

## Considered Options

- **项目从请求头取（`x-sfly-project`）**：列表、新建类接口的路径不用改。但按名字定位的资源在第二步之后要靠一个看不见的请求头才能确定是哪一个，日志、运行通知里的链接、浏览器地址都说不清指的是哪个项目，自建页面漏带请求头就会写到别的项目。
- **项目只从令牌取**：一个人在几个项目里就要几个令牌来回切，控制台的 Cookie 也没有地方放项目。
- **所有路径都带项目**（`/projects/:project/orchestrations/:id/…`）：ID 本来就确定了项目，再带一份就多出「两者不一致」这种情况，还要多改 41 个接口。
- **Agent 池共享，按项目授权**：Agent 上的文件能力不做沙箱（`agent/src/capabilities/fs.rs:3`），节点是任意 Python，共享 venv 按包名装（ADR 0002）；两个项目共用一台 Agent 时互相读得到、互相顶掉包。要补每项目的系统用户和环境，代价比装两个 Agent 大得多。
- **每个项目一个 PostgreSQL schema**：引擎的全局锁和周期扫描、指标的按天分区、迁移都要乘以项目数，Agent 那一层的问题一条没解决。
- **数据库的行级安全策略**：引擎要跨项目扫描租约和定时器，到处要开例外；检查放在契约路由一处、加上从路由清单生成的跨项目测试，更容易看全。
- **按项目签发一个注册凭据，名字随意**：装 Agent 方便，但工作台上的模型拿到它就能冒充项目里任何一台 Agent。改为按 Agent 签发。
- **会话构建和正式版本共用上传接口，按参数或版本号区分**：范围要看请求内容才能定，见「一处检查」。
- **只有「用到会话构建」的会话运行才不给密钥**：会话复制场景、用已发布的节点就能把参数打印出来，派到工作台的任务的原值落在模型读得到的目录里，见「助手会话」。
- **节点输出里的原值，下游拿到掩码**：不用另存原样的输出，但会悄悄改变节点之间传的值：节点把保密参数拼进一个地址或一份配置放进输出，下游拿到 `token=******`，要到下游鉴权失败才看得出来，也看不出是平台改了值。
- **继续在读取时打码**：参数改成引用、密钥可以替换之后，已结束的运行没有原值可以对照，打码就失效了，比现在更不安全。
- **场景版本里的保密默认值留在版本里，只靠接口打码**：版本不用改写，但原值永远留在数据库和备份里，项目密钥加密存放的意义少了一半。
- **每个成员按范围逐项勾选权限，不设角色**：灵活，但每加一个人都要想一遍；三种角色加平台管理员覆盖了现在的用法，角色只是范围的组合，以后好加。
- **argon2 或 bcrypt**：要原生模块，打不进单文件。scrypt 是 Node 自带的。
- **另做 CSRF 令牌**、**把跨域默认收窄成来源名单**：登录 Cookie 只在同源时用于有副作用的请求、跨域只认令牌之后，两者都不再需要；收窄跨域会让每个自建页面都要改控制面的配置。
- **审批做成在助手一侧拦截工具调用后挂起**：拦不住（模型有 shell），挂起的状态也不该在助手进程里（#442）。
- **留一个关闭认证的开关**：两套行为都要测，「内网里先关掉」会成为常态。

## Consequences

- 一次涉及数据库、全部 HTTP 接口、Agent 注册、命令行、API 客户端和前端的改造，按任务拆分逐个合入：先加能力（表、令牌、登录、Agent 凭据、测试基建默认带凭据），最后一步才在契约路由上强制，所以中间每一步合入后测试仍然全绿。测试基建要在强制之前就能带凭据：现在 150 个控制面测试文件和 81 个 e2e 的请求都不带凭据，大部分经 `apps/server/test/support/test-control-plane.ts` 的 `fetch` 和 `api-client.ts`，少数直接请求地址，e2e 里约 24 个文件自己写了昵称请求头。
- 发到飞书群里的消息也是打码后的：节点用 `ctx.notify` 发的消息、运行通知里出现的保密值，群里看到的是掩码。这是用户看得到的行为变化，写进发版说明和 `docs/guide/` 讲 `ctx.notify` 的地方。
- 写入时打码改的是日志、动作、输出、错误、进度、通知内容的写入路径，其中日志和动作明细是性能关键路径，改动的 PR 要贴 `pnpm perf` 的结果。引擎多存一份加密的原样输出，寿命同原值集合。原样输出删除之后，以后要做「从历史运行取上游输出」这类功能时，拿到的是打码后的值，到时要考虑。
- 重试按引用重新解析：同一次运行里不同的尝试可能拿到同一个密钥的不同值（中途被替换时）。
- Agent 的过渡窗口要由跨版本的自更新测试（ADR 0014）覆盖：旧 Agent 在新控制面上排空任务时，装包、上传产物、任务里下载产物都照常。
- API 客户端、命令行、自建页面都要换成令牌，列表和新建类接口的路径变了，是不兼容变化。真实使用方的离线导入要先建项目令牌。
- 助手对真实用户开放之前必须完成：身份、令牌、契约路由上的范围检查、Agent 凭据（含工作台）、会话令牌与待批准的操作、会话运行与工作台的密钥规则、会话的机器人勾选、写入时打码、工作台的出网名单，以及 #445 的第 1 项（删除飞书通知节点）和第 4 项（删除在线编辑者）。成员管理、项目切换（开放建项目要等名字的第二步）、Agent 与节点包的归属改造、项目密钥的加密存放与历史迁移、名字的第二步、能力端口的凭据在骨架之后；其中按名字引用的资源（Agent、节点包、飞书机器人）的项目检查要在能建第二个项目之前完成，只有默认项目和公共项目时它拦不住任何东西。
- 场景复制到另一个项目时，文档里的 Agent、节点包、飞书机器人名字按新项目解析，可能失效；预检给出提示。
- 本地账号要自己做改密码、停用、重置；没有单点登录，以后接反向代理头或 OIDC 时用预留的外部身份列。
- 修订的其他 ADR（各自末尾加了指针）：0004「不建模用户」的一半；0017「发布接口没有认证，保留前缀拦不住」与「等平台有了认证再统一处理权限」；0019「不做认证」（数据和接口层由本 ADR 处理，能力端口的凭据另做）；0020「能打开页面的人可以增删机器人」与「Webhook 明文保存」；0021「不做只读模式」与「昵称和经哪个 AI 编程助手不做校验」；0022「身份沿用昵称」与跨域的后果；0024「secret 预设参数明文保存」与「记下最后修改人的昵称」。

控制面的包索引（Python 索引一类，不需要凭据）在 #556 起除 `sfly` 之外也提供标准节点包 `sfly-std`（只列公共项目里已发布的版本，不列任何用户项目的节点包）；理由和范围见 docs/ARCHITECTURE.md §4.3。

公共项目只有平台管理员能写（#565）：发布节点包可以用过渡的查询参数 `POST /packages?project=public` 指明公共项目，访问检查对项目写在查询参数或路径里的写公共项目的请求，和带了凭据的、按 ID 定位的写公共项目的请求，要求平台管理员本人的登录或个人令牌，别的凭据 403（说明原因）、不带凭据 401，指明别的项目名 400；不带凭据和共享令牌的、按 ID 定位的写要到强制登录（#494）之后才落进这一条；路径带项目（#488）之后由路径里的项目替代这个参数。理由和范围见 docs/ARCHITECTURE.md §4.3 和访问检查一节。

停用期间的例外（#606）：用户被停用时，他的登录、令牌对别的接口一律失效（上面「用户」一条）；例外是他自己的登录在三个吊销自己的凭据的接口（登出、注销全部登录、吊销个人令牌）上还认，个人令牌只在吊销它自己时还认——只能用来吊销自己的凭据，吊销了的启用之后不会恢复。理由和范围见 docs/ARCHITECTURE.md 访问检查一节的「停用、注销」一条。
