# 每个 Agent 共用一个 venv，依赖冲突直接报错

每个 Agent 上的所有节点包都安装进同一个共享 venv；同一个包的不同版本不能共存，需要时就地切换；依赖冲突导致安装失败时，任务以 `env_error` 失败并展示完整的安装输出，不做自动隔离。我们接受"冲突直接暴露"，换取实现简单、安装快、磁盘占用小；这样做的前提是平台面向内网少量团队，节点包数量有限。

## Considered Options

- **每个节点包的每个版本使用独立 venv**：彻底隔离，但需要管理大量 venv、缓存和清理，被否决。
- **发布时锁定依赖（带哈希的锁文件）**：可复现性更好，但在共享 venv 中，锁定的版本反而更容易互相冲突，因此不采用。

## Consequences

- 安装或切换节点包时，必须与启动新任务互斥。
- SDK 运行时与执行器只能使用 Python 标准库，否则会和用户节点包的依赖冲突。
- 同一个 Agent 上的测试结果，可能因为其他节点包改动了共享依赖而发生变化；需要严格隔离的场景，应部署单独的 Agent。
