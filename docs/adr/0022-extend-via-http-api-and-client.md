# 平台的扩展方式是开放 HTTP API 和 API 客户端，不做进程内插件

平台自带的页面以编排画布为中心。专注某个业务的团队搭好场景之后，日常是换参数触发、看各环境的运行状况，需要自己的看板和触发页面。平台不为每种业务做页面，也不引入插件机制：把现有的 HTTP API 开放出来，提供一个 TypeScript 的 API 客户端，用户自己写、自己托管页面（调研见 `docs/research/platform-extension.md`）。

## 规则

- **只做 API 和 API 客户端。** 用户的自建页面是独立的前端项目，由用户自己托管，不属于平台，平台不托管也不在导航里展示它。
- **API 客户端是一个很薄的 TypeScript 包。** 它提供带类型的接口调用、断线自动重连的事件流订阅、下载地址的拼接和统一的错误类型。类型从 HTTP 契约（ADR 0007）生成；发布出去的包运行时不依赖 zod，不带 React 或 TanStack 的绑定，浏览器和 Node 都能用。
- **只开放现有接口，不为自建页面新增接口。** 客户端覆盖控制台和命令行在用的接口：场景、运行、日志、指标、产物下载、Agent、节点包、飞书机器人、控制台统计；不包含给 Agent 和安装脚本用的接口，也不包含在线编辑者。开放的接口不分稳定和实验性两档。
- **控制面默认允许所有来源的页面跨域调用**，另有配置项可以把允许的来源收窄成名单。
- **客户端和控制面同一个版本号、一起发布**，由控制面提供同版本的安装包，和 Python SDK 的做法一致（ADR 0010）。1.0 之前不保证跨版本兼容；版本不一致时客户端给出警告；破坏性的接口变更写进发版说明。
- **身份沿用昵称。** 写操作带昵称请求头（ADR 0004），客户端初始化时要求填昵称，并在 `x-sfly-client` 请求头里标明自己和版本号（ADR 0021）。
- **出现下面任何一种需求时重新考虑插件**：要在平台已有的页面里加内容；要在控制面执行的节点；要审批、资源锁、配额这类干预引擎的能力。

## Considered Options

- **进程内插件，照搬 DeepSeek Harness 的「一切皆插件」**：它的前提是单人本机、没有数据库事务、没有多用户，插件是进程内全信任代码。sfly 是内网共享的单进程控制面，引擎在一把锁和一个事务里推进运行，一个插件出错会影响所有运行。它自己也保留了事实上的特权内核，并且一直在收紧。
- **进程内插件，自己写小内核、引擎封闭、开出一套决策点**：能把审批、资源锁、控制面节点这类需求做成插件，但要重新组装控制面、改引擎状态机和前端结构，并把插件接口、事件、插槽都变成对外承诺。眼下没有需要它的具体需求。
- **节点包声明式地提供界面**（像现在声明图表那样）：只能覆盖平台预先做好的组件，表达不了用户想要的整页看板。
- **平台托管用户的页面**（像发布节点包一样发布页面，和 API 同源）：不用处理跨域，但平台多出发布、托管和导航三件事；以后做登录时，同源的用户页面会以查看者的身份调用接口，还要另做隔离。
- **跨域只允许名单里的来源，默认不允许**：能挡住第三方网页，但每多一个自建页面就要改控制面的配置。决定默认全部允许，保留收窄成名单的配置项。
- **发布到公开的 npm**：内网不一定访问得到，版本也可能和控制面不一致。
- **同时提供 React 组件库**：能让自建页面和控制台外观一致，但组件一旦对外就不能随控制台自由修改。

## Consequences

- HTTP 契约成为对外的承诺：改接口的路径、字段或语义会影响用户的自建页面，要写进发版说明。
- 没有登录时，内网用户在浏览器里打开的任何网页，都能调用他访问得到的控制面，包括触发和取消运行、增删飞书机器人。飞书机器人的 Webhook 地址在接口里本来就是打码的。
- 以后做登录时，默认允许所有来源的前提下浏览器不会带上 Cookie：自建页面的登录凭据只能是请求头里的令牌；要用 Cookie，就得把跨域改成来源名单。
- 自建页面和控制台一样靠轮询加单次运行的事件流刷新。事件推送和对外的 Webhook、跨运行的指标查询、运行列表的时间范围和翻页、入口参数的说明和可选项，这一阶段都没有。运行预设后来作为控制台的功能加入，接口随之开放（ADR 0023）。
- 服务端的自动化（例如运行失败后创建 Jira 缺陷）只能由场景里的节点，或者用户自己部署的服务调用接口来实现。
- 各团队的自建页面外观不统一，触发表单、日志、图表这类常见部件各写一遍。
- 契约包现在直接导出 TypeScript 源码，只在仓库内使用；API 客户端要有自己的构建和打包，并纳入统一的版本号。
