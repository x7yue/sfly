# 控制面直接调用飞书 Webhook 发通知，投递与运行状态解耦

一个场景要跑几小时甚至几天，工程师不会一直盯着运行页面，希望运行的关键时刻（压测开始、节点失败、运行结束、指标越界）能在飞书群里收到消息。硬约束是**发通知不能影响主流程**：通知发得慢、发送失败、飞书不可达时，链路照常执行，节点和运行的结果都不因此改变。所以通知统一由**控制面**发给飞书群的自定义机器人（**飞书机器人**），直接访问登记的 Webhook 地址里的主机；消息先写进控制面持久化的发送队列，再由控制面**投递**，投递的结果只记录，从不修改任何节点、任务、链或运行的状态。这是控制面第一次主动向外发 HTTP 请求。

## 规则

- **直接访问 Webhook 地址里的主机**，不写死飞书域名，私有部署的飞书也能用。不支持代理，部署者要保证控制面能直接访问飞书；飞书机器人开启 IP 白名单时，填控制面的出口 IP。
- **成功的条件是 HTTP 2xx 并且响应体里的 `code` 为 0**，单次请求超时 10 秒。飞书的错误码翻译成中文的原因和下一步；响应体里有错误码时以错误码为准（飞书对 9499 回 HTTP 400）。只有网络错误、超时、HTTP 429、5xx 和限流错误码 11232 值得重试，其余错误码（9499、19021、19022、19024 和未知的）直接算失败。
- **Webhook 地址当凭据对待**：完整地址明文保存在数据库里（和 `secret` 参数一样），只在界面、日志、投递记录和错误信息里打码，只露出开头和结尾，接口不返回完整地址，编辑时只能整个替换。平台没有认证（ADR 0004），所以能打开页面的人可以新增、替换、删除机器人，也可以点「发送测试消息」；打码只防止从页面和日志里读出地址，不防止有人替换地址。
- **机器人名称全局唯一，创建后不能修改**：场景和节点按名称引用，改名会让引用悄悄失效；要换名就新建一个再删除旧的。
- **「发送测试消息」不是投递**：它不经过发送队列，同步发出一条固定文本，只发一次，结果立即翻译成中文返回，用来在配好之后马上验证。
- **投递与运行状态解耦**：发送队列保存在 PostgreSQL 里，控制面重启后接着投递；同一个机器人的消息按入队顺序串行投递并限速（`ctx.notify` 与引擎在不同的事务里入队，所以入队前先拿这个机器人的事务级咨询锁，入队顺序就是提交顺序），退避和期限按控制面时间（ADR 0018）计算。投递的结果写进任务日志或运行详情，不改变任何状态。
- **投递的可靠性在投递这一层**：可重试的失败从 1 秒起逐次翻倍退避，最长 60 秒，从入队算起 10 分钟还没送达就记为失败；等着重试的消息仍是队首，同一个机器人后面的消息不越过它。每个机器人每秒最多 5 个请求、每分钟最多 100 个（飞书对自定义机器人的限制，重试也算，只记在内存里：重启后多发的那一点由 11232 的重试接住）。单个机器人排队超过 1000 条时丢弃最旧的，失控的循环刷不爆群。文本消息超过 20 KB 在组装请求体时截断（紧接着入队）。没有定时器：下一次尝试的时间记在消息上，周期扫描唤醒时按控制面时间判断是否到点。

## Considered Options

- **在 Agent 上发送**（沿用标准节点 `http_request` 的形态）：测试机常常访问不了外网；请求失败时节点跟着失败，后面的普通节点都被跳过，违反「不影响主流程」；日志和重试要靠 Agent 上的时间，而测试会改动 Agent 时间（ADR 0018）。
- **做成常驻的服务节点**（在一条子流程里常驻、替别的节点发消息）：ADR 0019 否决过同样的形态。它占一个槽位和一条子流程，子流程失败照样让运行变成 `failed`，每加一种通知需求就要再设计一种服务节点。
- **支持经 HTTP 代理出网**（读 `HTTPS_PROXY`、`NO_PROXY`）：不需要，不支持。控制面必须能直接访问飞书，访问不了时通知发不出去，运行不受影响。
- **支持签名校验**：要多保存一个签名密钥（又一个凭据），并且签名里的时间戳和飞书的时间相差超过一小时就被拒绝，要保证控制面时间准确。飞书机器人可以用关键词或 IP 白名单代替，开启签名校验时给出明确的中文提示，让用户改设置。
- **支持图片上传**：Webhook 机器人不能上传图片，要用图片就得再引入飞书应用凭据（`app_id`、`app_secret`）和另一套接口。图片只能用用户自己已有的 `image_key`。

## Consequences

- 控制面多了一项对外网络依赖：部署文档要写明出网和 IP 白名单的要求（README「部署与运维」）。控制面访问不了飞书时，通知发不出去，但运行不受影响。
- Webhook 地址可以是任意 http 或 https 地址，控制面会向它发 POST。平台没有认证（ADR 0004），能打开页面的人可以让控制面向它能访问到的任何地址发一条固定格式的请求（测试消息）；页面只显示翻译后的结果，不返回对端的响应内容（对端回的是飞书格式、带错误码时，错误说明里会带上它的 `msg`，其中的地址打码）。只写进文档，等平台有了认证再统一处理权限。
- 机器人的 Webhook 地址以明文保存：数据库备份和导出里有它，和 `secret` 参数一样需要保护。
- 后面的功能都复用这一处客户端和错误翻译：飞书通知节点、运行通知和 `ctx.notify` 的消息进入同一个发送队列，由它投递。
