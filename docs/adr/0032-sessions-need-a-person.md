# 建会话、对会话发话、停止会话只有人能做：个人令牌算人，项目令牌、会话令牌和 Agent 凭据不行

ADR 0027 里「会话在 ADR 0029 范围表里的一行」只写了范围（会话的写是「编辑」）和「会话令牌对会话只有读」，没有说项目令牌能不能建会话、发话、停止。这份 ADR 补上，并修订 ADR 0027 的那一行：范围够之外还要「凭据是人」。

决定：会话的三个写（建会话、对会话发话、停止会话）在「范围够（编辑）」之上还要「凭据是人」。

## 规则

- **算人的**：登录的用户、个人令牌。个人令牌是用户本人的凭据（命令行和 API 客户端用），发起会话的就是这个用户，权限不超出他自己。
- **不算人的**：项目令牌（服务账号，没有用户）、会话令牌（助手干活用的）、Agent 凭据、任务凭据：一律 403，读按各自的范围照常。
- **为什么要有一个人**：会话是某个人发起的，「谁」记在会话和用户的话上（会话的发起人、`user_message` 的作者），成果清单、会话触发的运行、待批准的操作都要回到这个人身上，批准时还要再查「发起人此刻有没有权做这件事」（ADR 0029）。没有用户的凭据没有可以查的发起人，会话的权限也就没有来源。
- **只在一处检查**：规则写在访问检查的范围表里（每类资源一格 `humanOnly`，表是 `Record<ResourceKind, …>`，新的资源类别要明确写它是不是），经同一处检查（ADR 0029）生效；接口声明里不重复写。
- **竖切期间不带凭据、带昵称的请求照旧**：它们没有身份，#494 起才拒绝。这条规则不改变这一点。

## Considered Options

- **项目令牌也能建会话**（让定时任务、CI 起会话）：会话没有发起人，批准和权限的检查都无从谈起。真有这种需要时，先给项目令牌加上「代表某个用户」的概念，另开 ADR。
- **个人令牌不算人**：命令行和 API 客户端起不了会话，却没有任何安全上的理由（它就是这个用户的权限）。个人令牌带来的用量问题（一个人同时开多少会话、开得多快）以后用额度和限制处理，不靠把个人令牌排除在外。

## Consequences

- 自动化暂时不能用项目令牌起会话；要用时按上面第一条另开 ADR。
- 新的资源类别加进范围表时要回答「写是不是只有人能做」，编译期就有人问。
- 助手自己（会话令牌）不能新建会话，也不能给别的会话发话或停止它们，不会让会话自己繁殖。
- 落实（#592）：「凭据是人」是白名单——只有登录的用户和个人令牌算人，其余凭据（项目令牌、会话令牌、以后新种类的）一律由 `writeNeedsPerson` 拒；范围表每一行都要写 `humanOnly`（布尔），漏写过不了类型检查，规则不再靠一条条写死的凭据判断。
