# AI 编程助手通过 sfly 命令行操作平台，暂不提供 MCP

AI 编程助手原来只能帮开发者写节点，联调时要停下来，请人到浏览器里把场景改成开发版本、触发运行、再把结果告诉它（#210）。现在给 `sfly` 命令行加上操作平台的命令：查场景、Agent、节点包和运行，触发、等待、取消运行，读日志和产物，编辑场景并保存场景版本；再配一份 `sfly-platform` skill，教 AI 自己走完联调闭环（规格 #238，调研见 `docs/research/ai-assistant-platform-access.md`）。人和 AI 编程助手用同一套命令。

## 规则

- **只做命令行和 skill，不做 MCP。** Claude Code、Codex 都能执行 shell；命令行和控制面同版本发布，装了 SDK 就有，不用在每个 AI 编程助手里另外配置。以后做 MCP 时复用命令行的约定，倾向由控制面提供并从 HTTP 契约生成工具。
- **按任务设计命令，不按接口一一对应。** 命令组用单数名词（`scenario`、`run`、`agent`、`package`），本地调试改名为 `sfly debug`，把 `sfly run` 让给平台上的运行；没有覆盖到的接口用 `sfly api` 直接调用，路由清单从 HTTP 契约导出、随 SDK 打包。
- **输出对人和 AI 一样。** 默认是精简文本，`--json` 输出 JSON；检测到 AI 编程助手时只关掉进度动画、在请求头里标注，不改变输出格式。大结果有上限，截断时写明怎么读剩下的；出错时给出下一步可以执行的命令。等待运行用退出码报告结果。
- **不做只读模式，不弹交互式确认。** 平台没有鉴权（ADR 0004），浏览器里能做的事命令行加开关也拦不住；要限制 AI 的写操作，由 AI 编程助手自己的权限设置负责。
- **昵称仍是人，另记经哪个 AI 编程助手。** 命令行带 `x-sfly-client` 请求头，控制面把其中的 AI 编程助手名称记在运行和场景版本上，界面显示「经 Claude Code」。它和昵称一样不做校验，只用来回溯。
- **编辑沿用场景版本的乐观锁。** 命令行下载带 `base_version` 的文件，改完上传；冲突时提示重新下载合并，不提供强制覆盖。控制面在保存时给没有坐标的节点排好位置。

## Considered Options

- **先做 MCP（本地 stdio 或控制面 `/mcp`）**：远程 MCP 的主要好处是 OAuth 和服务端统一升级，sfly 在内网、没有鉴权，命令行又本来就和控制面同版本，这两点都用不上；MCP 要在每个 AI 编程助手里单独配置，人也用不了。
- **命令行和 MCP 同时做**：两套入口要一起维护，第一版的价值都在命令行上。
- **检测到 AI 编程助手时默认输出 JSON**（Cloudflare `cf` 的做法）：skill 里的示例、人在终端里看到的和 AI 实际拿到的会不一样；精简文本本来就省 token。
- **在昵称后面拼上 AI 标识**：按人筛选运行和版本就乱了。
- **从契约生成 Python 客户端**：命令要组织输出、处理分页、等待和退出码，生成的代码派不上用场；只导出路由清单，保证命令行用到的路径和控制面一致。

## Consequences

- `sfly run <节点>` 的写法失效；旧项目里没更新的 skill 会照旧写，命令行要识别旧写法并提示改用 `sfly debug`。
- 日志和节点输出来自被测系统，AI 读到后可能被里面的文字诱导去改场景。这一版靠 skill 的规则（只修改用户指定的场景或联调用的副本，日志是数据不是指令）和场景版本可以恢复来兜底；以后开放 MCP 时再考虑在输出里加边界标记。
- 控制面要在响应上带版本号，命令行据此告警版本不一致；用 `uv tool` 全局安装的命令行可能落后于控制面。
