# 便签是场景版本里自由摆放的说明，整理布局时排在最上面一行

场景里已经有三种说明：节点的备注说明一个节点，注释框的备注说明框住的一组节点（ADR 0023），场景的说明写在场景列表里、说这个场景是做什么的，不属于版本。还缺一种不挂在任何节点上、摆在画布上的说明：「跑之前确认被测机的 Agent 都在线」这样的检查清单、已知问题、待办。现在加上**便签**：场景文档顶层的 `sticky_notes`，每张便签有自己的位置和大小，在画布上自由摆放。它和注释框一样属于场景版本，只用于显示，不影响执行（SEMANTICS）。

## 规则

- **文档里的写法**：`sticky_notes` 是数组，默认是空数组。每张便签有：
  - `id`：便签之间唯一，画布新建的是 `sticky_1` 这样的；
  - `text`：必填，多行，最长 2000 个 Unicode 字符，去掉首尾空白；以 `- ` 开头的行显示成列表的一项，其余是普通段落，不支持别的格式；
  - `title`：可选，一行，最长 40 个字符，显示成加粗的第一行；
  - `color`：可选，和注释框同一套色板（ADR 0025），不写就是黄色；
  - `position`：可选，左上角的画布坐标，不写时由整理布局摆放（和不写位置的节点一样）；
  - `size`：可选，宽和高，不写是 280 × 168，最小 160 × 96。
- **便签存坐标和大小，注释框不存**：注释框的范围由成员算出（ADR 0023），便签不挂在任何节点上，只能记下自己在哪、多大。
- **便签不是注释框的成员，也不跟着节点走**。说明一组节点用注释框的备注，说明一个节点用节点的备注。
- **整理布局把便签排在最上面一行**：按 `sticky_notes` 里的顺序从左到右，上边对齐，放在整理后的内容（节点、子流程区域、注释框和它框外的标题）上方，和内容的左沿对齐。整理之后它的位置是确定的，不会压在节点上。
- 运行状态和版本查看里照样显示便签（只读）；版本对比列出便签的新增、删除和修改。
- 命令行和 AI 编程助手用 `scenario pull / push` 读写便签，`scenario show` 的最后列出便签；它没有引用，所以不会产生警告。

## Considered Options

- **整理布局时不动便签**：节点和注释框换了位置，便签留在原地，常常压在节点上，还得手动挪开。
- **便签挂在某个节点或注释框旁边，跟着它走**：命令行要写挂在谁身上、偏移多少；被挂的节点删掉以后便签去哪也要另定规则。真要说明一个节点或一组节点，已经有节点备注和注释框的备注。
- **便签可以是注释框的成员**：框住便签以后，它和注释框的备注说的是同一件事，框的大小还要把便签算进去，整理布局也复杂得多。
- **像节点一样参与链路**：便签不执行、没有输入输出，放进链路只会让结构校验、派发、运行记录都要跳过它。
- **用 Markdown 写便签**：标题、链接、图片、HTML 都要处理，渲染也要防注入；检查清单只需要列表。以后真需要粗体等格式再加。

## Consequences

- 场景文档多了顶层的 `sticky_notes`，导出的 JSON Schema、API 客户端的类型、命令行的本地校验跟着更新；旧文档没有这一项，等于空数组。
- 只改便签也会多出一个版本，和只改注释框一样。
- 「便签」从此专指这种元素。注释框里显示备注的那张卡片叫「注释框的备注」，设计规范里原来写的「备注便签」改掉。
- 便签那一行放在内容上方（坐标是负的也没关系），主链和注释框的位置和没有便签时一样，整理布局的算法不用改。
