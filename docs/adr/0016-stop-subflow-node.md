# 子流程由显式的停止子流程节点结束，停止不算失败

「压测期间一直监控，压测结束就停」这类用法里，子流程上的节点会一直运行，而运行要等所有链结束才结束（SEMANTICS §6），主链结束也不影响子流程（§4）。我们新增一种控制面上的内置节点**停止子流程节点**：用户在链上的某个位置选择一个由本链触发的子流程（按子流程入口新增的名称选择），节点停止它及其下级子流程，等它们完全结束（包括其中的 always 节点）后才完成。被停止的任务、等待和未开始的普通节点记为新的状态「已停止」（`stopped`），不算失败。主链结束不会自动停止任何子流程。

## Considered Options

- **异步任务节点上加「主链结束时停止」开关**：主链完全结束（包括 always 清理）之后才停止，清理步骤可能先拆掉子流程还在用的东西，让子流程先报错失败；用户也无法控制停止发生在链上的哪个位置。把停止子流程节点放在主链末尾并设为 always，就能得到同样的效果。
- **主链结束后默认停止全部子流程，子流程可选择继续**：改变现有语义，已有场景版本的行为会变；还要为「需要跑完」的子流程增加例外选项和逐层传递规则。隐式行为比显式节点难理解。
- **复用取消（`cancelled`）**：被停止的子流程会把运行标成已取消或失败，而停止是场景的正常流程。

## Consequences

- 停止沿用取消的终止方式（取消标记、SIGTERM、宽限期后杀掉进程树），SDK、节点代码和 Agent 不变；「已停止」只在控制面、界面和 SEMANTICS 中出现。
- 一次运行里每个子流程最多一个实例（每个子流程入口恰好被一个异步任务节点连接，链不成环），所以按名称选择子流程在运行时总能对应到唯一的实例。
- 子流程入口新增必填的名称，场景内唯一；没有名称的旧版本以节点 ID 作为名称。停止子流程节点在版本里记录子流程入口的节点 ID，改名不影响引用。
