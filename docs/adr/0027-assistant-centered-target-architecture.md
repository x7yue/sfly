# 以平台内的助手为核心：目标架构和它的骨架

阶段 5（#418）要把平台做成以平台内的助手为核心的编排：用户在平台的网页里向助手提要求，助手写节点、调试、编排、运行、修到通过，不是让用户单独去用 pi。路线先经评测集（#443）验证：上限档的模型在写、修、编排、跨机器四类题上各 3 次全过，路线成立；内网档还没有数据，评测集留作度量，骨架不等它。

这份 ADR 记下两件事：目标架构的八条（#442 立项时定的），和骨架开工时（2026-11-21）负责人定的那一批决定。后者回答「pi 怎么嵌进来、跑在哪里、控制面和它之间说什么」，三个人（助手服务 #540、控制面的会话模块 #541、页面 #542）要在这些决定上并行，所以先定全；他们之间只隔着两样东西：平台的会话事件，和控制面发给助手服务的命令，它们的类型在 `@sfly/schema`（`packages/schema/src/sessions.ts`、`assistant-protocol.ts`）。

ADR 编号 0027 之前留给目标架构，一直没有写成文件，现在补上。

## 规则

### 目标架构（八条）

1. **助手不碰被测机。** 它的文件和命令只落在工作台上；被测机上的事由平台上的运行完成。
2. **开发中的节点经现有的发布和安装链路送到别的 Agent 上**（会话构建，GLOSSARY）。这条路是否走得通由 #456 确认；骨架不依赖它，但它必须先于出网名单（#498）：出网名单一上，工作台上的节点就够不着被测系统。
3. **平台不托管 git。** 工作区是工作台上的一个 git 仓库，每轮结束由平台（不是模型）提交；场景仍以数据库里的场景版本为准，工作区里的场景文件不是它的来源。
4. **项目是顶层租户**（细节在 ADR 0029）。
5. **共享 venv 现在不换。**
6. **能拦住助手的只有它够不着的东西**：会话令牌的范围、控制面上的审批（待批准的操作）、建会话时的勾选、工作台的容器和出网名单。提示词和 skill 不算边界。助手说的不作数：成果清单由平台的记录生成，不由助手自己报告。
7. **骨架现在开工，不等内网档的评测结果。** 评测集是产品的一部分，骨架之后经会话接口驱动。
8. **界面**：项目首页最终是会话列表；运行监控和版本对比是重点；画布降为读和小修。

### 骨架的决定

**嵌入方式：pi 的 RPC 模式，一个活动会话一个进程。** 会话闲置 15 分钟回收进程；下一条命令用同一条启动命令，从 pi 的会话文件恢复（新建和恢复是同一条命令）。不用 pi 的 SDK：依赖 pi 的面最窄——命令行参数、RPC 的命令和事件、模型文件的格式、扩展接口里的 `create*Tool` 和 `registerTool`；和评测集是同一种跑法，评测里量到的就是产品里的行为；进程边界兜底——卡住、内存涨只影响它自己，停止的最后手段是结束进程。

**循环在工作台之外**（评测集的臂 B）：读、写、编辑、命令四个工具经远程工具扩展落到工作台 Agent 的能力端口；工作台镜像里没有 Node 和 pi。依据是评测集的对照实验：两臂都是 12/12，轮数的中位数 15.5 对 14.5，用时没有变差；而「循环在工作台里」的加固配置在真实模型面前没有守住事先定下的两条（读得到 pi 进程环境里的令牌，能在 pi 的设置目录里建会被自动加载的扩展）。代价写明：命令退出后它起的后台进程被结束，模型跨两次命令「起一个服务再去测它」做不到；这个代价由评测集里加的一道题量出来（#552）。

**单独的助手容器，里面是助手服务，不是控制面的子进程。** 理由四条：

- pi 放在控制面里，就和控制面是同一个系统用户，够得着数据库连接串和所有项目的数据目录；而评测集的远程工具扩展里已经查出过会让模型够到 pi 所在机器文件的缺陷（两处，#540 要改），「自己的代码被带偏」不是假设。边界要是结构性的，不押在没人试过的 Node 权限开关上。
- 控制面一天到晚跑着测试运行，不和一批 pi 进程共用内存和重启。
- 控制面重启或升级不打断进行中的一轮。
- pi 的依赖树不进控制面镜像。

代价：多一个镜像和 compose 里的一个服务、一套内部协议和共享密钥、断线重连和事件补发。

**助手服务只做三件事**：起和看管 pi 进程；把 pi 的事件翻成平台的会话事件；执行控制面发来的命令（开始一轮、插话、停止、结束会话）。它不碰数据库，不存业务状态。它是**唯一依赖 pi 的代码**（新的 workspace 包 `apps/assistant`）：控制面、契约、页面只认平台自己的事件，以后换 pi 的版本、换嵌入方式，只动这一个包。这条靠 lint 守，不靠约定：`biome-plugins/pi-only-in-assistant.grit` 拦下 `apps/assistant/` 之外对 pi 的任何引入（`import`、`export … from`、动态 `import()`、`require`），例外只有 `evals/assistant/remote-tools/`（评测集臂 B 的原型扩展，删除臂 B 时一起删掉这条例外）。

**控制面和助手服务之间**（类型在 `@sfly/schema` 的 `assistant-protocol.ts`，不进控制面的 HTTP 契约）：HTTP/1.1 加 JSON，连接总是由控制面发起——命令是控制面发的请求，事件是控制面打开的一条 NDJSON 长连接。控制面的每个请求带 `Authorization: Bearer <共享密钥>`，助手服务按常量时间比较，缺了或不对返回 401；共享密钥短于 32 个字符时助手服务拒绝启动，控制面把助手当作「没有配置」，并在日志和就绪状态里写明原因。密钥不交给 pi 进程，不出现在任何事件和日志里。这一道不能省：工作台上的模型在网络上可能连得到助手服务的端口。事件流的每条记录带助手服务的纪元（每次启动生成的随机 ID）和纪元内递增的序号，断线重连用 `<纪元>:<序号>` 续传；纪元不同或序号太旧时，流的第一行告诉控制面中间有缺口。

**事件：类型在 `@sfly/schema`，持久的几类落库，增量只推不存。** 控制面把持久的几类（用户的话、一轮的开始和结束、助手的整条消息、工具调用和结果、提示、平台留下的记录、会话结束）写进 `session_events`，每条有会话内序号；文字增量、工具的输出、思考、排队状态、快照只推不存。浏览器用 SSE 加 `Last-Event-ID` 续上，刚连上时控制面补一条快照。pi 的会话文件只管模型的上下文，**不同步进数据库**：同步要追 pi 内部的条目格式，那是最容易随 pi 升级坏掉的一面。新增两张表 `sessions`、`session_events`（#541 建）。

**页面**：导航加「助手」，会话列表加输入框，加会话页；首页换成会话列表放在骨架验收之后（#553）。

**助手用工作台上的 `sfly` 命令行加两份 skill 操作平台，不给 pi 加平台专用的工具。** 上限档的 12 次评测里没有一次败在命令行上；ADR 0021 为 AI 编程助手定的做法（命令行加 skill，不做 MCP）这里沿用给平台里的助手。

**身份分三步。** ① 竖切只在开发环境：命令带昵称和 `AI_AGENT=pi`。② 骨架里签发会话令牌，按 ADR 0029 范围表里「会话令牌」那一列放行，运行和场景版本记下属于哪个会话（#495 的前一半，先于 #494 合入，否则助手的每条命令都 401）。③ 对真实用户开放之前做勾选、待批准的操作、密钥规则、出网名单（#495 的后一半、#496–#498）。

**模型**：部署者给助手容器挂 pi 格式的模型文件，密钥用环境变量引用；模型和密钥只在助手容器里。不需要模型转发口：pi 在模型的工具够不着的地方。

**工作台**：按用户文档的 `--dev` 装的普通 Agent 容器，加 git 和 ripgrep。工作区是持久卷上的 git 仓库，每轮由平台提交。**同一个项目同一时刻只跑一轮**，其余的排队并显示排第几；停止、上限、提交工作区、排队都以一轮为单位（GLOSSARY「一轮」）。

**远程工具扩展搬进产品前改两处**：不根据工具结果里的文字决定读本机的哪个文件；不根据工作台返回的内容在本机写任何文件。再加启动参数 `--no-extensions` 作第二道，让 pi 只加载平台自己指定的那一个扩展。

**评测集加「平台」臂**：经会话接口驱动，取代臂 B。

### 和 ADR 0029 的关系

这一节只写清读法，不改 ADR 0029 的正文：

- 资源类别 `session` 随骨架加进契约（#541）。会话构建的接口（资源类别 `session_build` 等）出现时再加：契约测试要求每个资源类别都有接口在用，所以不在没有接口的时候预先加。
- 会话接口的路径按 ADR 0029 的「项目从请求的哪里来」：列出和新建在 `/projects/:project/sessions`，其余按会话 ID 定位、路径里不带项目，项目从会话所在的项目得出。
- ADR 0029「迁移与过渡」里「登记工作台之前……这是骨架的前置条件」，读作**正式的工作台部署到有真实 Agent 的环境之前**的条件（#549 依赖 #492），不是竖切开工的条件：竖切只在开发和评测环境里跑。

## Considered Options

- **进程内 SDK**：依赖面最宽（内部类型和条目格式都进了控制面的代码），卡住或内存涨会拖垮同进程的别的会话，停止只能靠 pi 自己配合；也和评测集的跑法不同，量到的行为不是产品里的行为。
- **JSON 模式，每轮起一次进程**：进程起来之后不再接受命令，做不到插话。
- **循环在工作台里（方案乙）**：模型的命令和 pi 同在一台机器、同一个系统用户，加固配置在真实模型面前没有守住（见上）；两臂的结果和用时没有差别，换不来什么。
- **pi 做控制面的子进程，在 Node 的权限开关下运行**：边界押在没人试过的开关上；还是和控制面共用内存、重启和镜像。
- **把 pi 的会话条目同步进数据库**：要追 pi 内部的条目格式，每次升级都可能坏；只管模型上下文的东西不值得进库。
- **给 pi 加平台专用的工具**：命令行加 skill 已经够用（12 次里没有一次败在命令行上），专用工具会让助手的能力和人用的命令行分叉，也多一处依赖 pi 的扩展接口。
- **骨架里就做每个会话一个工作树和会话构建**：等 #456 的结论，现在做可能白做。
- **竖切之前先等 #489–#491 再给身份**：竖切只在开发和评测环境里跑，先带昵称；身份在骨架里分步补上（上面「身份分三步」）。

## Consequences

- 多一个镜像和一个服务；控制面和助手服务之间多了一套协议和一个共享密钥；断线重连、事件补发、pi 进程的回收和恢复都是新的运行状态要管（#545）。
- 后台进程留不住：命令退出后它起的后台进程被结束，「起一个服务再去测它」做不到；评测集里加一道题量出代价（#552）。
- 一个项目一次一轮：两个人同时用同一个项目时，第二个人要等。竖切里直接拒绝（`project_busy`），#544 起改成排队。
- 会话事件的类型成了控制面、助手服务、页面共用的契约：事件改名、响应里的枚举多值都算 API 客户端的不兼容变化（`docs/agents/branching-and-release.md`「PR」一节），所以骨架里出现的取值一次定全（`@sfly/schema`），后面的任务只是开始产生它们。
- 换 pi 的版本或嵌入方式，只动 `apps/assistant`。
- **什么证据会推翻「循环在工作台之外」**：内网档的模型在「平台」臂上按 #443 事先定的三条判定明显不如臂 A——通过的会话少超过 1 次、轮数的中位数超过 1.3 倍、只在一臂出现两次以上的失败类型。那时按这里的接缝换方案：写一个在工作台里运行的助手服务变体（pi 用本地工具、主动连控制面、说同一套协议），会话接口、页面、事件表都不变。
- 评测集的臂 B 在「平台」臂做出来后删除（#552），连同 lint 规则里对 `evals/assistant/remote-tools/` 的那一条例外。
- 文档：`docs/ARCHITECTURE.md` 由做出对应部件的任务写（助手服务 #540、会话模块 #541、部署 #549）；GLOSSARY 加了「助手服务」「一轮」。
