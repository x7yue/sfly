# 节点用 `${{ run.state }}` 在派发时拿到整个运行的状态

真实使用方最想要、平台没有的一件事：一个放在链末尾、总是执行的汇总节点，想知道前面的节点各自是成功、失败、被取消还是被跳过，失败的原因是什么。节点只能引用本链上游的输出，失败的节点没有输出，所以汇总节点只能按「上游有没有输出」猜运行停在了哪里，写不出失败原因，也分不清失败和取消。飞书通知节点被移除（ADR 0028）之后，「运行结束时按结果发一条自己想要的通知」只剩在节点里做这一条路，这条路原来是断的。

决定：加一个引用 `${{ run.state }}`，它在**任务派发时**解析成这次运行此刻的状态，接到节点的一个普通输入上。形状叫运行状态（`RunState`，GLOSSARY），定义只有一份，和运行摘要接口（`GET /runs/:id/summary`）给出的运行状态相同。

## 规则

- **机制是引用。** 和 `params`、`nodes.<id>.outputs.<key>` 一样写在场景文档里，派发时解析，解析出的值和别的输入一样记在这次尝试上，运行视图里看得到汇总节点当时拿到了什么。只能整值引用（运行状态是对象，拼不进字符串），只能写在包节点的输入里：异步任务节点的参数映射在子流程创建时解析并按值复制，子流程里的节点拿到的会是一份过时的状态，所以写在那里保存时警告、触发时阻断，子流程里的节点要用就在自己的输入里引用。
- **范围是整个运行**，不论引用它的节点在哪条链上：已经创建的全部链实例，每个带它那条链上的全部节点。这是观察，不是传值；「只能引用本链前面的节点」管的是输出。子流程里的节点只想看自己这一支时，按链实例的上下级关系自己筛。
- **内容**：运行的状态、取消请求、到此刻为止的结果（`result_so_far`）、按失败先后排的最终失败节点（`failures`）、引用者自己（`self`），以及每个链实例的子流程名称、层数、上级链实例、触发它的异步任务节点、自己的状态，和每个节点的状态、尝试次数、起止时间、错误（错误类型、失败原因一行、异常信息本身、出错的位置）。不含任何节点的输入、输出、日志、动作、堆栈、每次尝试的明细：输出是「原样传给下游」的数据通道，这里的内容一律打码，两者不混；要全文的人打开运行的链接或读运行摘要接口。以后加字段只增不改，读它的代码按「多出来的字段忽略」写。
- **时刻**：任务派发时，和把这次尝试记为「准备中」在同一个事务里；重试时每次尝试各解析一次。引用者自己总是 `dispatched`，排在它前面的本链节点一定已经结束，排在它后面的是 `pending`；其他链实例上的节点是那一刻的状态。
- **不改变调度**：引用它不构成对任何节点的依赖，不让引用者等待任何东西，引用了它的节点和没引用的节点就绪、派发的时机相同。要让汇总看到某个子流程的最终结果，把汇总节点放在停止这个子流程的节点后面。
- **只有引用了它的节点才读**：引擎在派发时看这个节点的输入里有没有 `run.state`，有才读运行状态，读取走运行的统一读取（`readRuns`）加一档只多读每次尝试的错误的 `state`，查询次数与运行里的节点数无关；没有引用它的节点，派发时的查询和以前一样。
- **打码与大小**：错误信息按这次运行的保密参数的值打码，读取时统一完成。失败原因一行最长 300 个字符，异常信息最长 2000 个字符，截断时有标记；整份超过 256 KB 时从 `failures` 的末尾起去掉异常信息，直到放得下，并在顶层标出被截断。异常信息和堆栈在执行器的失败结果里是分开的字段，Agent 上报时拼成「异常信息 + 空行 + 堆栈」存下，这里从第一个独占一行、顶格的 `Traceback (most recent call last):`（或异常组的 `  + Exception Group Traceback …`）处拆开；没有堆栈的错误（配置错误、超时、Agent 掉线）整段是异常信息。
- **让人和助手不忘了接这根线**：SDK 的 `sfly.RunState` 类型在输入 schema 上带标记（`x-sfly-type: run_state`）。必填的这种输入没接、或写了别的值（字面值、别的引用），保存时警告、触发时阻断，警告里直接写出该填 `${{ run.state }}`；画布加节点时预填；接到不带标记的普通输入（json）上也允许。节点拿到的是一个普通的字典，执行器不为它开特例。
- **运行通知保留**，作为兜底：汇总节点有执行不到的时候（强制取消、它自己失败或它的 Agent 掉线、主链结束之后才失败的子流程）。

## Considered Options

- **逐节点引用**（`${{ nodes.<id>.status }}`、`.error`）：汇总节点要为每个上游接一根线，节点类型的签名因此和某一个场景的形状绑死；引用只能指向本链前面的节点，子流程里的节点失败时主链末尾的汇总节点一个也够不着。
- **平台不声不响填的特殊输入**：数据进节点从此有两种机制，场景文档里看不出这个节点读了整个运行的状态；必填检查、执行器、本地调试、单测都要为它开特例。
- **执行时查询**（`ctx.run.nodes()`）：结果取决于执行到哪一刻，事后重放不出来；任务进程现在没有到控制面的读通道，新开一条要给任务发凭据（任务凭据只能下载产物，ADR 0029）。
- **「等某个子流程自己结束」的节点、运行结束钩子**：新的执行概念，现在没有使用依据；真有需要时另开任务。
- **把输出、日志、动作、堆栈放进运行状态**：输出是数据通道，不打码也不限长；日志、动作和堆栈要全文的人读运行摘要接口。

## Consequences

- 引用语法多了 `run.state`，静态检查（`@sfly/orchestration` 的 `run-state-references.ts`）、画布的引用补全和新增节点时的预填跟着加；警告多了 `reference_run_state_embedded`、`reference_run_state_misplaced`、`input_run_state_missing`、`input_run_state_value`。docs/SEMANTICS.md §2.7 是执行语义的完整写法。
- 契约和 SDK 多了运行状态的定义：`@sfly/schema` 的 `RunState`（导出 JSON Schema `run-state.schema.json`），SDK 的 `sfly.RunState`（`TypedDict`）和 `sfly.testing.run_state`；两端共用一张用例表 `testdata/run-state-cases.json`（控制面的投影函数和 SDK 的类型都对着它测）。
- 任务派发的协议没有变：只是派发前多读一次库（引用了 `run.state` 的节点），状态机、租约、重试和 Agent 一侧都没改，所以 `verify-task-dispatch` 的 TLA+ 模型不用改。
- 运行摘要接口（`GET /runs/:id/summary`）和这里共用同一个投影函数，两处的差别只在限制：接口不截断错误信息，节点的输入有长度和大小的上限。
- 出错位置（`error.location`）是执行器算出、存在任务上的（#513），和失败原因一起打码；节点自己没有出错（超时、Agent 掉线等）时为空。
