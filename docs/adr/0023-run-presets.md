# 运行预设是场景的设置，预设参数由控制面锁定

团队搭好场景以后，日常的用法是换参数触发（ADR 0022）：同一个场景按几套固定的参数反复跑。现在每次都要在运行抽屉里重新填，或者靠「再次运行」带上一次的参数，可是 secret 参数带不过来，选错一个值这次运行就跑偏了。ADR 0022 把运行预设列为这一阶段不做，出发点是不为自建页面新增接口，并没有说控制台不需要它。现在在控制台里加上**运行预设**：一个场景可以保存多套入口参数的取值，每套只固定其中一部分参数（**预设参数**），其余参数在触发时照常填写；触发时选用一套，预设参数不能修改。接口随控制台一起开放给 API 客户端。

## 规则

- **运行预设是场景的设置，不属于场景版本。** 它和运行通知一样，改了立即生效，不产生新版本；复制场景时一并复制，归档、恢复时原样保留。预设只覆盖入口节点的参数，不覆盖子流程参数、Agent 选择和节点参数。
- **按参数名称取值，只对照最新版本。** 最新版本新增的参数在预设里算作非预设参数。预设参数被删除、改名，或者保存的值不符合它现在的类型时，预设**失效**，不能用来触发；不会悄悄丢掉那个值。保存场景版本时，如果有预设会因此失效，给出警告并列出这些预设，但不阻止保存，和结构校验的做法一致。
- **锁定由控制面执行。** 触发请求里带上预设的 ID，再加上非预设参数的值。控制面在补默认值、检查类型的同一步填入预设的值；请求里给 secret 预设参数填了任何值（即使和预设里的值相同），给其他预设参数填了不同的值，或者预设已经失效，就拒绝触发。secret 预设参数不接受相同的值，因为接受还是拒绝会让调用方反复猜测、推断出 secret 的原值；是不是 secret 以最新版本的声明为准。运行上记下预设的 ID、触发时的名称和预设参数的名单。
- **secret 预设参数**：和触发时传入的值一样明文保存。接口只返回打码后的值，不返回原值，编辑时只能整个替换。
- **同时修改时，后保存的覆盖先保存的**，预设上记下最后修改人的昵称和时间，不做乐观锁。
- **命令行只加两件日常要做的事：用预设触发（`sfly run start --preset`）和查看预设（`sfly scenario show`）。** 维护预设用控制台，或者用 `sfly api` 直接调用接口。这样做的依据是 ADR 0021「按任务设计命令」。

## Considered Options

- **放进场景版本**：每改一次预设就多一个版本，和链路的改动混在版本历史里；改预设时还会和正在编辑画布的人冲突。运行总是绑定最新版本，预设用不着版本。
- **只在界面上锁定**：直接调用接口或命令行就能改掉预设的值，「不可修改」只停留在显示上。
- **参数被删除或改名时丢掉那个值，预设照常可用**：参数改名以后，它会落到默认值上，用户却以为跑的是预设里的值。
- **预设保存全部参数的值，不区分预设参数**：要么一个场景为每种取值组合各建一个预设，要么全部可以修改，那就只是预填，不是锁定。
- **像场景版本一样做乐观锁**：预设内容少，改得也不频繁；出了冲突，代价只是重新填几个值。
- **由自建页面自己保存预设**（ADR 0022 的现状）：每个团队各做一遍，控制台和命令行都用不上。

## Consequences

- HTTP 契约新增预设的接口，触发请求加了可选的 `preset` 字段，预检、运行详情和运行列表的响应多了字段。这些都只是新增，不算 API 客户端的不兼容变化。
- 数据库里多了一处明文的 secret 值，和场景版本里的默认值、运行参数一样需要保护。
- 运行通知的卡片多了一行「预设」，内容是触发时预设的名称。
- 入口参数仍然没有说明和可选项。
