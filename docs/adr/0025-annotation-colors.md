# 注释框可以选颜色，色板避开状态色

注释框有一个可选的 `color`，从六种颜色里选：灰（默认，不写就是灰色）、蓝、绿、黄、橙、粉。它和标题、备注一样属于场景版本，只用于显示，不影响执行（SEMANTICS §1.6）。颜色是场景作者选的分类色，只用来在画布上分开几个注释框，例如四个阶段各一种颜色，缩小看全图时一眼分得开；它不表达状态，所以是设计规范「彩色只用来表示状态」的一个例外，范围只限注释框（之后的独立便签也用这套色板）。

色板里刻意没有三种颜色：青色只给执行中、键盘焦点和调度连线；红色表示失败，失败节点的红色描边放在红色底板上也会认不出来；紫色是子流程区域的颜色，框住子流程的注释框是紫色时两者分不开。六种颜色在 OKLCH 里亮度相同、只换色相，色度压得比状态色低：换颜色时节点卡片和底板的对比不变，彩色底板也不会比状态标记更抢眼。框里三层明暗固定：注释框的备注最亮、底板居中、节点卡片最暗，灰色和彩色都一样。

标题写在框外左上方，是一个和框同色的胶囊（选了颜色后底色就是这个颜色）。调研（docs/research/canvas-annotation-groups.md §1 第 1 条）建议「框的标题不要长得像节点」，主流是横跨框宽的标题栏或框里左上角的文字；这里仍然用胶囊，因为它和节点卡片在三处分得开：它在框外、不在卡片所在的那一层；它是注释框的颜色，节点卡片永远是中性的 `raised`；它只有一行加粗的字，没有站点灯、端口和第二行。横跨框宽的标题栏会把框顶占掉一条，缩小看全图时和框里第一行节点挤在一起；框里左上角的文字在彩色底板上要另配文字色，缩小后也不如胶囊显眼。

## Considered Options

- **照搬 LibTV 的十色色板（含红、青、紫、白）**：红、青和状态色撞，紫和子流程区域撞，白色底板比所有内容都亮。
- **只用灰色，不开放颜色**：节点多、注释框多的场景缩小看全图时，几个灰色底板只能靠标题区分；用户明确要颜色。
- **标题做成横跨框宽的标题栏（ComfyUI、n8n、UE 的做法）**：框顶多占一条，缩小视图时标题栏和框里第一行节点挤在一起；胶囊在框外，不占框里的地方。
- **颜色写成任意色值（十六进制）**：命令行和 AI 写场景时会写出和状态色相近的颜色，底板的亮度也没法保证，卡片在上面可能看不清。

## Consequences

- 只改颜色也会多出一个版本，和改标题一样。
- 不写颜色和写 `gray` 都是灰色：画布选回灰色时去掉这一项，版本对比也把两种写法当成同一种。
- 色板以后加颜色时要守住同一条亮度线，并避开状态色和子流程的紫色；`design-rules.test.ts` 检查每种颜色的文字对比度和三层明暗。
