# Agent 上产生的数据同时记 Agent 时间和控制面时间

测试经常要改 Agent 机器的系统时间，Agent 与控制面的时钟不一致是常态，而且可能在任务执行中途向前或向后跳变；同时 Agent 上记下的时间是排查与溯源的依据，要能和被测系统自己的日志对上。因此我们规定：**控制面时间**是唯一的基准时钟，运行和链路的时间线、耗时、超时、等待节点（定时节点也按控制面时间理解）、排序、去重和保留期都只看它；**Agent 时间**作为被测机器上的事实原样记录和展示，不做范围检查，也不参与任何调度、排序或过期判断。在 Agent 上产生的每条日志、进度和指标点都带两个时间：Agent 时间，以及它发生时刻对应的控制面时间。后者由 Agent 用单调时钟打点、控制面按连接和心跳时测得的**时钟偏差**折算，而不是控制面收到它的时刻，这样断线期间排队的数据和按秒合并的指标也落在正确的位置。

规则：

- Agent 在连接和心跳时带上自己的当前时间，控制面据此计算时钟偏差：在 Agent 列表上展示，在任务开始和结束时各记一次；Agent 时间在任务执行中途跳变超过 2 秒时，Agent 自己（比较 Agent 时间与单调时钟，断线期间也照常）往本机正在执行的任务的日志里各写一行提示，记下跳变前后的时间和变化量。偏差的绝对值不到 2 秒时视为一致，页面不提示。
- 指标图表的横轴用控制面时间，悬停时显示 Agent 时间；Agent 时间倒退时曲线连续，不丢点。日志面板默认显示 Agent 时间，可以切换成控制面时间；点击日志在时间线上定位时用控制面时间。下载的日志两个时间都带。节点详情在偏差达到 2 秒时同时给出两种时间的开始和结束。
- 产物额外记录文件在 Agent 上的修改时间（Agent 时间），与上传时间（控制面时间）一起展示；下载时不还原修改时间。
- 页面上的"已运行"等时长按控制面时间计算，不依赖浏览器时钟。
- Agent 本地任务目录的保留期按真实流逝的时长计算，不看 Agent 时间；Agent 或机器重启后从头计时。
- 节点代码不需要改动，SDK 也不提供获取控制面时间的接口。本地调试只有 Agent 时间，行为不变。
- 改动之前存下的数据只有 Agent 时间，不做回填，缺失的那一项显示为未记录。

## Considered Options

- **只用控制面时间**（Agent 上的数据一律按控制面收到的时刻记）：实现最简单，但丢掉了排查时最需要的被测机器上的时间，也没法和被测系统的日志对照；断线排队和按秒合并的数据还会挤到收到的那一刻。
- **只用 Agent 时间**（改动之前日志、进度和指标的做法）：同一次运行里多台 Agent 的数据没法放到同一根时间轴上；保留期和分区被异常日期带偏，Agent 时间比控制面快 613 天时，指标点全部被当作时钟异常丢弃，页面上看不到任何数据。

## Consequences

- 协议里日志行、进度、指标点、产物上传、连接和心跳都要增加时间字段；指标的分区和保留期改按控制面时间，同一序列内的顺序也改按控制面时间判断。
- 折算出的控制面时间有误差，量级是一次网络往返；Agent 或机器重启后单调时钟重新开始，要在重新连接后重新测量偏差。
