# 快速开始

sfly 是测试编排平台：节点包里用 `@node` 声明的 Python 函数，由测试机上的 **sfly Agent** 执行，在控制面上编排成场景运行。当前控制面的地址是 `{{SFLY_URL}}`，版本 `{{SFLY_VERSION}}`。

只需要一台 Linux（x86_64 或 aarch64，WSL 也可以）和 `curl`。uv、Python、`sfly` 命令行都由安装脚本和 Agent 从控制面和镜像准备好。

从零开发第一个节点包有两种方式：交给 AI 编程助手，或者自己照着文档做。两种方式走的是同一套步骤、读的是同一套文档。

## 用 AI 编程助手开始

用 Claude Code、Codex 这类 AI 编程助手开发时，把下面的提示词复制给它，在「需求：」后面写上节点要做什么。它会自己用 `curl` 读取这套文档的原文，按下面「自己手动开始」的步骤，从检查环境一直做到发布。

```prompt
请帮我开发一个 sfly 节点包。sfly 的文档索引在 {{SFLY_URL}}/llms.txt：先用 curl 读取它，再读其中的「快速开始」页，按「自己手动开始」的步骤逐页读取原文并照着做，每一步达到「完成」再做下一步。项目创建后，以项目里的 .agents/skills/sfly-node-dev/SKILL.md 为准。

需要注册令牌，或者需要我在控制面页面上操作（例如联调时在场景里运行）时，停下来告诉我；令牌不要写进项目文件。发布前把包名、版本和改动摘要给我，等我同意再发布。

需求：
```

过程中需要你来做的事：

- **写清需求**：节点要做什么、需要哪些参数、输出什么、什么情况算失败。
- **提供注册令牌**：控制面要求令牌时，向平台管理员索取后交给它。
- **在场景里联调**：它装好开发版本后，在场景里把节点包的版本选为 `dev（开发版本）`、Agent 选它装好的开发机 Agent，运行后把结果告诉它。
- **确认发布**：已发布的 `包名@版本` 不能覆盖，确认包名、版本和改动摘要无误后再让它发布。

## 自己手动开始

按顺序读下面各页，照着做，每一步达到「完成」再做下一步。

1. **检查环境并安装**：先确认是 Linux（`uname -sm` 输出 `Linux x86_64` 或 `Linux aarch64`；其他系统不支持，WSL 可以），再在开发机上用一条命令安装 sfly Agent，加 `--dev` 同时装好 `sfly` 命令行。见 [安装 Agent](install-agent.md)。
   - 完成：`sfly --version` 输出 `sfly {{SFLY_VERSION}}`，这台机器的 Agent 在线（[Agent 管理](/agents) 页面，或 `curl -s {{SFLY_URL}}/agents` 的列表里 `status` 是 `online`）。已经装过当前版本时跳过安装。
2. **初始化**：`sfly init` 创建节点包项目，带示例节点、单元测试和给 AI 编程助手的 skill。见 [初始化项目](init-project.md)。
   - 完成：在项目目录里 `uv run pytest` 全部通过。已经在 `sfly init` 创建的项目里时跳过这一步。
3. **开发**：用 `@node` 写节点，`ctx` 上报日志、进度、指标、产物。见 [开发节点（SDK 参考）](sdk-reference.md)。
   - 完成：`uv run ruff format`、`uv run ruff check`、`uv run pytest` 全部通过，每个节点都有成功路径和失败路径的单元测试。
4. **本地调试**：`sfly run` 在开发机上直接执行节点，不经过控制面和 Agent。见 [本地调试](local-debug.md)。
   - 完成：输出、日志、指标、产物符合预期；错误参数、节点抛出异常、Ctrl-C 取消各至少跑过一次。
5. **联调**：`sfly dev` 把项目以开发版本装到本机 Agent，在真实场景里运行。节点要连真实的被测系统、或要验证和上下游节点的配合时做这一步。见 [联调](integration.md)。
   - 完成：在场景里选开发版本运行，结果符合预期。
6. **发布**：`sfly publish` 发布到控制面，场景锁定版本使用。见 [发布](publish.md)。
   - 完成：输出 `已发布 <包名>@<版本>`。

节点发布后在场景里编排：要和主链并行的节点（例如压测期间一直监控）放进子流程，用停止子流程节点结束它，见 [子流程与停止子流程](subflows.md)。平台还提供与业务无关的标准节点（执行命令、HTTP 请求、断言、系统监控等），见 [标准节点](standard-nodes.md)。运行的关键时刻（开始、失败、结束、指标越界）要发到飞书群，见 [飞书通知](feishu-notify.md)。

## 读取原文

每一页都有 Markdown 原文，地址已经填好当前控制面，可以直接用 `curl` 读取；全部页面的地址列在索引里：

```sh
curl -s {{SFLY_URL}}/llms.txt
```

| 地址 | 内容 |
|---|---|
| `/llms.txt` | 全部页面的原文地址 |
| `/docs/<页>.md` | 一页的 Markdown 原文，例如 `/docs/install-agent.md` |

已发布的节点包见 [节点包管理](/packages) 页面，在线的 Agent 见 [Agent 管理](/agents) 页面。
