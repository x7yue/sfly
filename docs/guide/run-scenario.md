# 运行场景

在控制台里触发场景的运行：填写入口参数，看触发前检查；常用的几套参数存成**运行预设**，下次选一下就能触发。用命令行触发见 [用命令行操作平台](platform-cli.md)，在自己的页面里触发见 [用 API 客户端做自己的页面](api-client.md)，三种方式用同一批运行预设。

## 运行抽屉

[场景列表](/orchestrations)（卡片和表格）与画布上的「运行」打开运行抽屉。运行监控页的「再次运行」打开同一个抽屉，入口参数用上一次运行的值预填，secret 参数不带，要重新填；上一次用了运行预设的话，预设也一起带上，见下面的「再次运行」。

- **入口参数**按入口节点的声明生成表单：必填的参数留空、数字和 JSON 的格式不对，都不能触发。留空的参数由控制面按默认值填入。secret 参数默认打码，可以临时显示 5 秒。
- **触发前检查**列出结构与引用检查、节点包版本是否锁定、引用的 **sfly Agent** 是否在线。有阻断项时「触发运行」不可点；sfly Agent 不在线只是提醒，任务排队，等它上线再执行。
- 触发之后，抽屉切换为运行摘要：各链的进度、进行中的节点、最新日志。可以打开运行监控，运行中的还能取消。

## 运行预设

同一个场景常常按几套固定的参数反复跑，例如「压测 A 集群」「压测 B 集群」：大部分参数相同，只有几个要改。**运行预设**把一套入口参数的取值存在场景上：

- 每个预设有场景内唯一的名称（区分大小写，最多 40 个 Unicode 字符，一个 emoji 算一个）和可选的说明（最多 200 个 Unicode 字符）。
- 预设固定入口参数里的一部分，这些参数叫**预设参数**；其余参数触发时照常填写。
- 预设是场景的设置，**不属于场景版本**，和运行通知一样：修改后立即生效，不产生新版本；复制场景时一并复制；场景归档期间也能修改。

### 触发时选用预设

运行抽屉顶部的「运行预设」选择框里有「不使用预设」和场景的各个预设（按名称排序），最后一项是「管理预设…」。

- 选中一个预设，预设参数就锁定：只读，标签带锁的图标，帮助文字写「由预设 <名称> 固定」，secret 参数只显示打码。只需要填其余的参数。
- **锁定由控制面执行**，界面上的锁定只是显示这条规则。触发请求带着预设，预设参数一定取预设里保存的值。命令行用 `sfly run start <场景> --preset <名称>` 按预设触发（见 [用命令行操作平台](platform-cli.md)），自建页面在触发请求里带上预设的 ID。给预设参数传了不同的值，触发会被拒绝；secret 预设参数传任何值都会被拒绝。
- 预设在触发的那一刻读取。触发之后再修改预设，不影响已经开始的运行。
- 换预设，或者切回「不使用预设」时，换之前和换之后都能编辑的字段保留已经填的值；原来锁定、现在解锁的字段回到参数的默认值。浏览器拿不到 secret 预设参数的值，所以解锁之后它也是默认值，要重新填。
- 打开抽屉时，默认选中这个场景在这个浏览器里最近一次触发时用的预设，每天按同一个预设触发只需要点一下。记的是触发成功的那一次的选择：选了没有触发不算；用了某个预设就记下它，不使用预设触发就清掉，下次打开是「不使用预设」。记住的预设已被删除或已失效时，默认回到「不使用预设」。换一个浏览器不会带过去。

### 把填好的参数存为预设

不使用预设时，选择框上方有「存为预设」。它打开新建预设的表单，带上抽屉里现在填的值：填了值、改过默认值的参数默认勾上，没动过的参数不勾。secret 参数也勾上，但值要重新输入。起一个名称，看一眼勾选的参数，保存之后，选择框里就能选到这个新预设。

### 新建和管理预设

选择框底部的「管理预设…」，或者场景列表那一行「更多操作」菜单里的「运行预设…」，打开同一个管理对话框，可以新建、编辑、复制、删除预设。从抽屉里打开时，关掉对话框以后选择框随之刷新。

- 新建表单列出最新版本的全部入口参数，每个参数一行：勾选「预设」把它固定下来，并填上固定的值。勾选时先填上默认值。勾选的参数必须填值（字符串不能为空），按声明的类型检查；至少勾选一个参数。入口节点没有声明参数的场景不能新建预设。
- secret 参数也能设为预设参数。值明文保存在控制面，界面和接口只返回打码后的值。编辑时 secret 参数显示「已填写」，点「替换」才重新输入，不改它就不用再填。
- 复制预设时取一个新名称，值（包括 secret 的值）一起复制，再改几个值就得到相近的一套。删除预设不影响已有运行上记下的预设名。
- 列表里写着每个预设固定了哪些参数，以及最后由谁、什么时候修改。两个人同时修改同一个预设时，后保存的覆盖先保存的，不做冲突检测。

### 失效的运行预设

预设按参数名称对照场景的最新版本。预设参数在最新版本里已不存在（被删除或改名），或者保存的值不符合它现在的类型时，预设**失效**：不能用来触发，也不会悄悄丢掉那个值、改用默认值。

- 选择框里能看到失效的预设，但选不了，名称后面写明原因，例如「已失效：参数 host 已不存在」。
- 在管理对话框里编辑它：已不存在的参数单独列出，取消勾选；类型不对的值标为错误，重新填写。保存之后恢复可用。失效的预设也可以只改名称和说明。
- 在画布上保存版本时，如果这次改动会让预设失效，保存之后会提示，并列出这些预设和原因。版本照常保存，方便你顺手更新预设。
- 最新版本新增的参数不影响预设，它们算作非预设参数。参数的默认值、是否必填、是否敏感有变化，也不影响预设。

### 运行上的记录

用了预设的运行记下预设的名称和预设参数的名单。运行监控页顶栏显示「预设：<名称>」，悬停或点击能看到哪些参数来自预设；运行记录列表里，场景名旁边显示「预设：<名称>」；飞书运行通知的卡片里有一行「预设」；`sfly run show` 也写明用的预设。预设之后改名或删除，旧运行上显示的仍是触发时的名称。

### 再次运行

对用了预设的运行点「再次运行」，抽屉按这个运行记下的预设来选：

- 预设还能用时，默认选中同一个预设，这个选择优先于浏览器里记住的最近一次用的预设。预设参数锁定，显示的是预设**现在**的值，不是上一次运行用的值，所以先改了预设再点「再次运行」，用的是新值。其余参数用上一次运行的值预填，secret 参数照旧不带，要重新填。
- 预设已被删除或已失效时，回到「不使用预设」，全部参数用上一次运行的值预填（secret 参数除外），表单上方写一行原因，例如「预设 压测 A 集群 已删除」「预设 压测 A 集群 已失效：参数 host 已不存在」。已失效的预设修好以后，再点一次「再次运行」会重新选中它。
- 上一次没用预设时，和以前一样，不使用预设，用上一次运行的值预填。浏览器里记住的预设不会套上来，那是别的运行用过的。

再次运行认的是预设本身，不是名称：删除预设以后再新建一个同名的预设，它不算原来那个预设。

## 关注项

盯一个浸泡或压测运行的人，关心的往往只有几个数：被测进程的 CPU 和内存、母单量和子单量。**关注项**让场景作者从本场景节点声明过的图表里挑出这几张，最多 8 个，按挑选的先后排列。

### 怎么设置

1. 在画布的编辑模式里选中一个包节点，打开检查器的「说明与指标」页。
2. 「图表」下面列出这个节点类型声明的全部图表，每张图表带一个「关注」开关。点开关，这张图表就成为本场景的关注项，再点一次取消。图表上方写着「本场景的关注项已用 N / 8」。
3. 用满 8 个以后，没打开的开关禁用，旁边写着「先在场景设置的「关注项」页移除一项」。已经失效的项（见下面）也占名额。

- 关注项以**图表**为单位，只有这一种开关。节点类型声明的每个指标都画在某张图表里（没被任何图表引用的指标，平台生成一张同名的默认图表），所以每个声明过的指标都能挑到；场景里不能新建或修改图表，图表的样式来自节点包。
- 关注项是场景的设置，**不属于场景版本**，和运行通知、运行预设一样：改了立即生效，不产生新版本，不要求先保存场景。同时修改时，后保存的覆盖先保存的。场景记下最后一次修改：谁、什么时候、改了什么（例如「把「下单延迟」移到第 6 位」）。
- 控制面按已保存的最新版本检查新加的关注项：节点要在最新版本里，它锁定的节点包版本要声明了这张图表。刚添加、还没有保存成场景版本的节点（或改了节点类型、节点包版本的节点），它的开关禁用，先保存。
- 复制场景（包括联调副本）时关注项一起复制，副本上的最后修改记为复制的人，写「复制自「<源场景>」」。

### 排序、改名、移除

不选中任何节点时，右侧是「场景设置」，它的「关注项」页按显示顺序列出本场景的全部关注项：每行写名称、来源节点和图表，能找到图表的项还标出它是数值还是图表。

- **排序**：拖动行首的手柄，或者点每行的上移、下移箭头（读屏读作「上移 X」「下移 X」）。只用键盘时用这两个按钮，焦点跟着那一项走，读屏会播报「X 移到第 N 位，共 M 项」。
- **改名**：直接改行里的名称，离开输入框或按回车写入，按 Esc 放弃这次输入。清空（或者写成图表标题）就回到图表标题。同一张图表用在不同节点上时，起不同的名字就能分开。名字最多 40 个字符。
- **移除**：点行尾的 ×（读屏读作「移除关注项 X」），列表上方马上出现「撤销」，点它就把列表恢复成移除之前的样子。「撤销」只管刚做的这一次移除：你接着改了别的，或者页面读到别人改了列表，它就消失。
- **最后修改**：列表上方写着最后一次修改的人、时间和改了什么，例如「lin · 01-01 10:02，把「下单延迟」移到第 6 位」。只记最后一次，没有历史。

这些修改和「关注」开关一样立即生效，正在跑的运行也跟着变。

### 失效的关注项

关注项按节点 ID 和**图表标题**引用图表，不会因为场景的改动悄悄消失，而是保留在列表里、继续占名额，在「关注项」页里写明失效的原因：

- **节点不在最新版本里**：节点被删除了。页面上写「只在运行 vN 及更早版本时显示」（接口里带上包含它的最后一个版本号），运行绑定在这个版本及更早的版本时，这一项照常显示。
- **图表不存在**：节点还在，但它锁定的节点包版本没有这张图表，例如新版本改了图表的标题，或者节点换成了别的节点类型。页面上写「这个版本的节点没有图表 X」。

已经在列表里、后来失效的项可以原样保留、排序和改名。移除之后再想加回去，就是新加入的项，要通过上面的检查；只有移除之后马上撤销不用检查，它把列表恢复成移除之前的样子。

### 用 API 客户端读写

`orchestrations.update` 的请求体加了 `focus_items`：整份替换场景的关注项，每项 `{ node_id, chart, title }`，`chart` 是图表标题，`title` 是场景作者起的名字，不写或写空字符串时用图表标题（最多 40 个 Unicode 字符，一行）。空数组清空关注项。不合格时返回 400，列表不变：

| 错误码 | 原因 |
|---|---|
| `focus_items_limit` | 超过 8 项，已经失效的项也算 |
| `focus_item_duplicate` | 同一个节点的同一张图表出现了不止一次 |
| `focus_item_unknown_chart` | 新加的项引用了最新版本里没有的节点，或者这个节点的节点类型没有这张图表 |

写入和现在一样的列表不算修改。读取用 `orchestrations.get`：`focus_items` 是按作者顺序排好的列表，每项带 `status`：`ok`（再带 `chart_type`，图表在最新版本里声明的类型 `line`、`area`、`bar` 或 `stat`，`stat` 是数值卡）、`node_missing`（带 `last_version`，包含这个节点的最后一个版本号；复制场景时带过来、没有任何版本包含它的项为 `null`）或 `chart_missing`；`focus_edit` 是最后一次修改（`updated_by`、`updated_at`、`summary`），从没改过时为 `null`。场景列表（`orchestrations.list`）不带关注项。
