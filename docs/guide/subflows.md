# 子流程与停止子流程

场景从入口节点开始，主链上的节点逐个执行。要和主链**并行**的步骤——例如压测期间一直采集系统指标、跟随日志文件——放进子流程：主链上的异步任务节点触发它，主链不等待，接着往下执行。到了该结束的时候，用停止子流程节点把它停掉。

本页的操作都在 [场景编排](/orchestrations) 的画布上完成。

## 子流程

1. 在添加节点菜单里选「子流程入口」，填写**子流程名称**，画布上出现一块子流程区域，区域标题就是名称。把子流程要执行的节点接在子流程入口后面。
2. 在链上放一个「异步任务」节点，从它底部的调度出口连线到子流程入口。子流程入口声明的参数，在异步任务节点的检查器里填写：可以是常量，也可以引用前面节点的输出。
3. 运行到异步任务节点时，它触发一次子流程，立即成功，主链继续。子流程里也可以再放异步任务节点，触发下一级子流程。

子流程名称在场景内唯一，在画布、检查器和运行视图里用来区分子流程。名称为空或重复时，保存只给出警告，触发运行时会被拒绝。没有名称的旧版本场景，以子流程入口的节点 ID 作为名称。

主链和子流程互不影响：

- 子流程失败不影响主链继续执行，主链失败也不会取消正在运行的子流程。
- 运行要等**所有链**都结束才结束。任一条链失败，运行记为失败。
- 主链结束**不会**自动停止子流程。子流程里有一直运行的节点时，运行会一直停不下来，要用停止子流程节点结束它。

## 停止子流程节点

在添加节点菜单里选「停止子流程」，放在链上需要停止的位置，在检查器的「要停止的子流程」里按名称选择。候选只有本链在这个节点之前触发的子流程，以及它们触发的下级子流程；不能停止自己所在的链、上级链或其他分支上的子流程。场景版本里记录的是子流程入口的节点 ID，之后改子流程名称不影响引用。

运行到停止子流程节点时：

- 子流程还没被触发（例如异步任务节点因为前面失败被跳过），或者它和它触发的下级子流程都已经结束：立即成功，什么也不做。
- 否则停止这个子流程（如果它还在运行），以及它触发的、仍在进行的下级子流程：
  - 正在运行、排队的任务按取消的方式终止：节点代码里抛出 `sfly.Cancelled`，`finally` 里的清理照常执行，宽限期 10 秒后强制杀掉进程树。节点不需要为「停止」写专门的代码，写法同 [开发节点（SDK 参考）](sdk-reference.md) 的「取消与超时」一节。
  - 正在等待的定时节点、Sleep 节点和还没开始的普通节点记为「已停止」。
  - 子流程里的 always 节点照常执行。
- 停止子流程节点等这些子流程**完全结束**（包括其中的 always 节点）才成功，等待期间显示为「等待中」。所以它后面的步骤执行时，子流程已经不再运行。

被停止的任务和节点显示为「已停止」，与「已取消」「已跳过」「失败」区分开。停止是场景安排好的正常流程，**不算失败**：子流程在停止前没有失败、其中的 always 节点也没有失败时，子流程记为成功，运行的结果不会因为停止变成失败或已取消。子流程在停止前已经失败的，仍然记为失败。

停止子流程节点的输出：

| 输出 | 说明 |
|---|---|
| `status` | 子流程的最终结果：`success` 或 `failed`（运行被取消、子流程按取消结束时也是 `failed`）；子流程没有被触发时为 `null` |

子流程失败不会让停止子流程节点失败，后面的节点可以引用这个输出，自己判断子流程的结果。

停止子流程节点可以设为 always：主链前面的节点失败时，它照样去停止子流程。用户取消整个运行时不由它处理，所有链按取消的规则结束（再次取消即强制取消），已经记为「已停止」的保持不变。

## 典型编排：压测期间一直监控，压测结束就停

```text
主链：         入口 → 准备 → 异步任务 → 压测 → 停止子流程「监控」(always) → 清理(always)
                              │
                              └─调度─▶ 子流程「监控」：子流程入口 → 系统监控 → 收尾(always)
```

1. 新建子流程「监控」，放一个一直运行到被停止的监控节点；监控结束后需要做的收尾（例如汇总采样结果）放在它后面，设为 always。
2. 主链上准备步骤之后放异步任务节点，调度到「监控」；接着放压测节点。
3. 压测之后放停止子流程节点，选择「监控」，打开 always：压测失败时也照样停止监控。
4. 停掉被测进程、删除日志文件这类清理步骤放在停止子流程节点**之后**，设为 always。停止子流程节点等「监控」完全结束才完成，清理执行时监控已经停干净，不会因为被测进程或日志文件先被拆掉而报错。

结果：

- 压测成功：系统监控节点记为「已停止」，收尾照常执行，「监控」子流程成功，运行成功。
- 压测失败：后面的普通节点被跳过，停止子流程节点和清理照常执行，运行因为主链失败记为失败；「监控」子流程仍是成功。

监控节点就是一个循环到被停止的普通节点，收尾写在 `finally` 里：

```python
import os
import time

from sfly import Context, Metric, node


@node(
    title="负载监控",
    metrics=[Metric("load1")],
    primary_metric="load1",
)
def watch_load(ctx: Context, interval: float = 1.0) -> None:
    """每隔 interval 秒采样 1 分钟平均负载，直到被停止或运行被取消。"""
    ctx.log.info("开始监控")
    try:
        while True:
            ctx.metric("load1", os.getloadavg()[0])
            time.sleep(interval)
    finally:
        ctx.log.info("监控结束")
```

包节点的执行超时默认 1 小时（[开发节点（SDK 参考）](sdk-reference.md) 的「取消与超时」一节），超时后任务失败。压测可能超过 1 小时的，在检查器里把监控节点的超时调到比压测更长。
