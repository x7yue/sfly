# 飞书通知

场景要跑几小时甚至几天，不用一直盯着运行页面：让运行的关键时刻（压测开始、某个节点失败、运行结束、指标越界）发到飞书群里。消息由**控制面**直接发给群里的自定义机器人，Agent 不需要访问外网。

有三种方式发消息，用同一批飞书机器人，消息格式也一样：

| 方式 | 适合 | 在哪里设置 |
|---|---|---|
| 飞书通知节点 | 链上的固定位置：运行开始、某一步之后、链尾收尾 | 画布，添加节点菜单里的「飞书通知」 |
| 运行通知 | 运行结束时自动发一张卡片，不用编排节点 | [场景编排](/orchestrations) 列表里「更多」菜单的「运行通知…」 |
| `ctx.notify` | 节点执行到一半发现指标越界，立刻通知 | 节点代码 |

**通知不会影响主流程。** 消息交给发送队列后，节点立即成功；飞书不可达、返回错误、机器人被删除，都不会让节点失败，也不会改变运行的结果，后面的节点照常执行。投递的结果只写在日志和运行详情里。

## 登记飞书机器人

1. 在飞书群的「设置 → 群机器人」里添加「自定义机器人」。「安全设置」选**自定义关键词**或 **IP 白名单**，不要选签名校验（sfly 不支持）。复制它的 Webhook 地址。
2. 打开 [飞书机器人](/feishu-bots) 页（侧边栏，快捷键 `G` `F`），点「登记机器人」，填名称和 Webhook 地址。**名称全局唯一，创建后不能修改**：要换名就新建一个再删除旧的。场景和节点按名称选择机器人，Webhook 地址不会写进场景。
3. 点这一行的「发送测试消息」，立刻看到结果。失败时页面用中文写出原因和下一步，常见的见下文「群安全设置的常见错误」。

- 列表里的 Webhook 地址只露出开头和结尾，日志和错误信息里也是。点「替换地址」整个换掉，看不到原值。**Webhook 地址相当于一个凭据**：拿到它的人就能往群里发消息。它在控制面的数据库里明文保存，平台没有登录和权限，能打开页面的人都能新增、替换、删除机器人，也能发测试消息。
- 页面显示每个机器人最近一次投递的时间和结果，以及积压（还在排队）的消息条数，可以据此发现某个群发不出去。
- 删除机器人之前，页面列出引用它的场景：飞书通知节点、「飞书机器人」类型的参数的常量值和运行通知的设置。允许删除；删除后，它还没发出的消息被丢弃。
- 复制场景到另一个环境时，把机器人换成那个环境的群即可。

## 飞书通知节点

在添加节点菜单里选「飞书通知」。它在控制面执行，**不需要选 Agent，不占 Agent 槽位**。轮到它时，控制面解析输入、组装消息、放进发送队列，同一时刻把节点记为成功。节点没有输出。

检查器里选**飞书机器人**（已登记的机器人的下拉框，也可以用「插入引用」改为引用入口参数，触发时再决定发到哪个群），再选**格式**：

| 格式 | 填写 | 发出的消息 |
|---|---|---|
| 文本 | 文本；「@所有人」开关 | 纯文本。打开「@所有人」时在正文末尾加上 `<at user_id="all">所有人</at>`。正文里自己写的 `<at user_id="ou_xxx">名字</at>` 原样发出，知道某人的 open_id 就能 @ 到他 |
| Markdown 卡片 | 标题、标题颜色（蓝、绿、橙、红、灰）、正文（Markdown） | 一张卡片：标题加颜色，正文是 Markdown。不用手写卡片 JSON |
| 原始消息 | 完整的飞书请求体（JSON） | 原样发出，不改写、不补字段。富文本、自己设计的卡片、模板卡片都走这一种 |

文本、标题和正文里可以写引用：输入 `$` 或点「插入引用」，选择入口参数或前面节点的输出，发出时替换成实际的值，所以消息里能带上目标 QPS、版本号这类值。

- 原始消息里，JSON 的每个字符串字段都可以写引用。引用先于序列化解析，所以引用的值里有引号、换行也不会弄坏 JSON，可以放心往卡片里填动态内容。
- 引用的输出不存在时（例如前面的节点被跳过了）取 `null`，内嵌在文字里就显示 `null`，节点照常发送。飞书通知节点无论是否设为 always，都按 always 节点的规则解析引用，所以它不会因为引用问题失败。
- 可以设为 always：放在链尾，不管前面成功还是失败都发一条收尾消息。想在运行一开始通知「压测开始」，把它放在入口节点后面。
- 解析或组装出错时（机器人的值不是字符串、原始消息不合格、文字里的引用解析出了对象……）节点不会失败：它在节点日志里写一条 warning，然后成功，消息不发送。
- 保存时选了没登记的机器人给出警告，触发运行前的预检把它作为阻断项；机器人引用入口参数时，触发时按实际传入的值检查。机器人只能是机器人名称，或整个引用入口参数：引用前面节点的输出、或把引用夹在文字里，保存时给出警告，触发时同样被拦下。运行到节点时机器人已被删除的，不发送，节点照常成功。
- 切换格式时，其他格式里填过的内容留着，但不显示、不参与检查和解析。

### 消息大小

飞书的请求体不能超过 20 KB（紧凑 JSON 按 UTF-8 编码的字节数，一个汉字 3 字节）：

- 文本：超过时截断正文，末尾加上「…（已截断）」，「@所有人」仍在最后。
- Markdown 卡片：超过时截断正文，同样加上「…（已截断）」。标题长到连截断后的正文都放不下时，不发送，节点日志里写 warning。
- 原始消息：**不截断**（截断会弄坏结构）。只校验它是一个对象、`msg_type` 是 `text`、`post`、`image`、`share_chat`、`interactive` 之一、不超过 20 KB；不合格的不发送，节点日志里写明原因。图片消息只能用自己已有的 `image_key`，平台不上传图片。

## 运行通知

运行结束时自动发一张卡片，不用在链上加节点，适合「失败了就在群里喊一声」。在 [场景编排](/orchestrations) 列表里，点场景的「更多」菜单，选「运行通知…」：

| 设置 | 说明 |
|---|---|
| 飞书机器人 | 发给哪个群。留空就是关闭运行通知 |
| 触发条件 | 仅失败；失败和取消；总是（成功、失败、取消都发） |
| 卡片标题 | 留空时用场景名。群里有多个场景或环境时，可以写成「【订单压测-A 环境】」，一眼分清是哪个 |
| 附加说明 | Markdown，放在卡片正文的最前面，可以 @ 负责人，写明环境或该找谁 |

这些设置**不属于场景版本**，和名称、说明一样：修改后立即生效，不产生新版本，不用重新保存和触发；复制场景时一并复制。运行结束时，控制面读取场景**当前**的设置，满足条件就发卡片。

卡片的结构由平台固定：

- 标题颜色表示结果：成功绿色、失败红色、取消灰色，副标题写明「运行成功」「运行失败」「运行已取消」。
- 正文依次是：附加说明（如果有）、场景名、运行编号（运行 ID 的前 8 位）、触发人、开始时间和耗时、失败的节点和它所在的链（最多列 10 个，其余写总数）。时间按控制面所在的时区显示并带上时区，部署时设置控制面的 `TZ`。
- 最后是「查看运行」按钮，打开这次运行。链接由控制面的 `SFLY_PUBLIC_URL` 拼出，没有配置时不显示按钮。

运行抽屉里有一行「运行通知」，显示这张卡片的状态：排队中、已送达、投递失败（写明原因）、已丢弃、未发送（写明原因，例如选中的机器人已被删除）。只是提示，从不改变运行的状态。运行还没结束、场景没有选机器人、结果不满足触发条件的运行没有这一行。

选中的机器人被删除后，设置弹窗里有提示，触发运行不会被拦截；运行结束时记为「未发送」。

「运行开始」的通知不属于运行通知：在入口节点后面放一个飞书通知节点。

## 在节点代码里发：`ctx.notify`

节点执行到一半就要通知（压测发现 p99 越界），用 `ctx.notify`：

```python
import sfly
from sfly import Context, FeishuBot, node


@node(outputs=["passed"])
def stress(ctx: Context, qps: int, alert_bot: FeishuBot) -> dict:
    ...
    if p99 > 500:
        ctx.notify(alert_bot, f"p99 {p99} ms，超过 500 ms", at_all=True)
        ctx.notify(
            alert_bot,
            message=sfly.feishu.card("压测告警", f"**p99** {p99} ms，超过 500 ms", "red"),
        )
    ...
```

- 机器人要声明成 `FeishuBot` 类型的参数传进来（画布上是机器人下拉框，触发前检查它已登记），不要在代码里写死名称，也不要自己请求 Webhook 地址。只发给这种参数引用的机器人，其他名称不发送，任务日志里有警告。
- `ctx.notify(bot, text)` 发文本；`ctx.notify(bot, message=...)` 发原始消息（完整的飞书请求体）；`sfly.feishu.card(title, markdown, color="blue")` 组装 Markdown 卡片，和画布上的「Markdown 卡片」格式一样。
- 调用后立即返回，**投递失败永远不会抛出异常**，节点不会因为通知失败或变慢。投递结果写进这个任务的日志：送达是 info，失败或被丢弃是 warning。
- 原始消息不合格（不是对象、`msg_type` 不对、超过 20 KB）时，不发送，任务日志里写明原因，调用也不抛异常。
- 本地调试（`sfly run`）不真的发送，只把要发的请求体打印出来，不会骚扰群；单元测试里用 `sfly.testing.run_node` 结果的 `notifications` 断言每条消息的机器人和请求体。

完整的接口说明见 [开发节点（SDK 参考）](sdk-reference.md) 的「`ctx.notify`：飞书通知」。

## 投递的规则

三种方式的消息进入同一个发送队列，由控制面投递：

- **按顺序**：同一个机器人的消息按产生的先后串行发出，不同机器人互不影响。
- **限速**：每个机器人每秒最多 5 条、每分钟最多 100 条，超出的排队等候。积压超过 1000 条时丢弃最旧的，一个失控的循环刷不爆群。
- **重试**：网络错误、超时、HTTP 429、5xx 和飞书的限流错误码 11232 会退避重试，间隔从 1 秒起逐次翻倍，最长 60 秒；从入队算起超过 10 分钟还没送达就记为失败。其他错误不重试，只发一次就记为失败。
- **不丢**：消息存在数据库里，控制面重启后接着投递。
- **结果在哪里看**：飞书通知节点和 `ctx.notify` 的结果写进这个任务的日志（送达是 info，失败是 warning）；运行通知的结果显示在运行抽屉里；机器人页显示最近一次投递和积压条数。

## 群安全设置的常见错误

飞书的错误码会被翻译成中文，写明原因和下一步（测试消息、任务日志、机器人页的最近投递里都能看到）：

| 错误码 | 原因 | 怎么办 |
|---|---|---|
| 19021 | 群里的机器人开启了签名校验，sfly 不支持 | 在机器人的「安全设置」里关闭「签名校验」，改用「自定义关键词」或「IP 白名单」 |
| 19022 | 控制面的出口 IP 不在机器人的 IP 白名单里 | 把**控制面**访问飞书的出口 IP 加进白名单（不是 Agent 的 IP；经代理出网时填代理的出口 IP） |
| 19024 | 消息里没有机器人设置的关键词 | 每条消息都要包含群里设置的关键词之一：把关键词写进消息文本、卡片标题或运行通知的附加说明里，或者改用「IP 白名单」。测试消息里有「sfly」 |
| 9499 | 飞书认为请求格式不对 | 发原始消息时最常见：检查请求体是不是飞书要求的 JSON，`msg_type` 和 `content` 要对应；测试消息出现它时，检查 Webhook 地址是不是飞书机器人的地址 |
| 11232 | 触发了飞书的频率限制 | 自动退避重试，不用处理；飞书建议避开整点和半点发送，那时更容易被限流 |

其中 19021、19022、19024、9499 不重试，直接记为失败，修好群设置后再发。控制面连不上飞书（超时、连接失败）时，错误信息会提示检查网络和代理，见下文「部署时的出网要求」。

## 部署时的出网要求

这是控制面第一次主动向外发 HTTP 请求（ADR 0020）：

- **控制面所在的机器要能访问飞书**：官方飞书是 `open.feishu.cn` 的 443 端口；私有部署的飞书按登记的 Webhook 地址，控制面直接访问地址里的主机，不写死飞书域名。Agent 不需要出网。
- **只能经代理出网时**，给控制面设置环境变量 `HTTPS_PROXY`（http 地址用 `HTTP_PROXY`）和 `NO_PROXY`（不走代理的主机，逗号分隔，例如私有部署的飞书）。控制面启动时读取；docker compose 在 `.env` 里写，会传进容器。
- **IP 白名单填控制面的出口 IP**，经代理出网时填代理的出口 IP，不是 Agent 的 IP。
- **运行通知的「查看运行」按钮**需要 `SFLY_PUBLIC_URL` 配成浏览器能访问的控制面地址；时间显示用控制面所在的时区，设置 `TZ`。
- Webhook 地址当凭据保护：数据库里明文保存，数据库备份里有它；平台没有认证，能打开页面的人可以管理机器人。
