# 飞书通知

场景要跑几小时甚至几天，不用一直盯着运行监控页：让运行的关键时刻（压测开始、某个节点失败、运行结束、指标越界）发到飞书群里。消息由**控制面**直接发给群里的自定义机器人，Agent 不需要访问外网。

有两种方式发消息，用同一批飞书机器人：

| 方式 | 适合 | 在哪里设置 |
|---|---|---|
| 运行通知 | 运行结束时自动发一张卡片，不用写代码 | [场景编排](/orchestrations) 列表里「更多」菜单的「运行通知…」 |
| `ctx.notify` | 节点执行到一半发现指标越界，立刻通知；也可以做成一个发消息的节点，放在链上的固定位置（运行开始、某一步之后、链尾收尾） | 节点代码 |

做成节点的话，它和别的包节点一样在 Agent 上执行、占一个槽位：链尾总是执行的收尾通知要等到有 Agent 可用（受排队超时约束）。运行通知由控制面直接发，不占槽位。

**通知不会影响主流程。** 消息交给发送队列后，节点和运行都不用等它；飞书不可达、返回错误、机器人被删除，都不会让节点失败，也不会改变运行的结果，后面的节点照常执行。投递的结果只写在日志和运行抽屉里。

> 以前画布上有「飞书通知」节点，已经移除（ADR 0028）。旧版本里还留着的这种节点只读显示，不能运行：触发前的预检会拦下，保存新版本前要先把它删掉。替换办法是用 `ctx.notify` 在节点代码里发飞书消息，见下文「在节点代码里发：`ctx.notify`」。

## 登记飞书机器人

1. 在飞书群的「设置 → 群机器人」里添加「自定义机器人」。「安全设置」选**自定义关键词**或 **IP 白名单**，不要选签名校验（sfly 不支持）。复制它的 Webhook 地址。
2. 打开 [飞书机器人](/feishu-bots) 页（侧边栏，快捷键 `G` `F`），点「登记机器人」，填名称和 Webhook 地址。**名称全局唯一，创建后不能修改**：要换名就新建一个再删除旧的。场景和节点按名称选择机器人，Webhook 地址不会写进场景。
3. 点这一行的「发送测试消息」，立刻看到结果。失败时页面用中文写出原因和下一步，常见的见下文「群安全设置的常见错误」。

- 列表里的 Webhook 地址只露出开头和结尾，日志和错误信息里也是。点「替换地址」整个换掉，看不到原值。**Webhook 地址相当于一个凭据**：拿到它的人就能往群里发消息。它在控制面的数据库里明文保存，平台没有登录和权限，能打开页面的人都能新增、替换、删除机器人，也能发测试消息。
- 页面显示每个机器人最近一次投递的时间和结果，以及积压（还在排队）的消息条数，可以据此发现某个群发不出去。
- 删除机器人之前，页面列出引用它的场景：「飞书机器人」类型的参数的常量值和运行通知的设置。允许删除；删除后，它还没发出的消息被丢弃。
- 复制场景到另一个环境时，把机器人换成那个环境的群即可。

## 运行通知

运行结束时自动发一张卡片，不用在链上加节点，适合「失败了就在群里喊一声」。在 [场景编排](/orchestrations) 列表里，点场景的「更多」菜单，选「运行通知…」：

| 设置 | 说明 |
|---|---|
| 飞书机器人 | 发给哪个群。留空就是关闭运行通知 |
| 触发条件 | 仅失败；失败和取消；总是（成功、失败、取消都发） |
| 卡片标题 | 留空时用场景名。群里有多个场景或环境时，可以写成「【订单压测-A 环境】」，一眼分清是哪个 |
| 附加说明 | Markdown，放在卡片正文的最前面，可以 @ 负责人，写明环境或该找谁 |

这些设置**不属于场景版本**，和名称、说明一样：修改后立即生效，不产生新版本，不用重新保存和触发；复制场景时一并复制。运行结束时，控制面读取场景**当前**的设置，满足条件就发卡片。

卡片的结构由平台固定：

- 标题颜色表示结果：成功绿色、失败红色、取消灰色，副标题写明「运行成功」「运行失败」「运行已取消」。
- 正文依次是：附加说明（如果有）、场景名、预设（只有用了运行预设的运行才有，写触发时的预设名称）、运行编号（运行 ID 的前 8 位）、触发人、开始时间和耗时、失败的节点和它所在的链（最多列 10 个，其余写总数）、关注项（见下面）。失败的节点写成「显示名称（节点 ID）」，例如「主链：创建测试用户（create_user_1）」，没有显示名称时只写节点 ID；名称取自这次运行锁定的场景版本。时间按控制面所在的时区显示并带上时区，部署时设置控制面的 `TZ`。
- 场景设了[关注项](run-scenario.md)时，失败的节点之后有一段「关注项」，每项一行，写运行结束时的值，最多 8 行：「母单量：1.3M 单」。顺序和运行监控的概览一样：有异常的项（例如来源节点失败）排在最前，其余按场景设定的顺序。值的写法和运行监控里的读数一样（`1.3M` 是 1284814）。图表有多个序列时，写最近更新的那个序列，序列名放在名称后面：「撮合进程 CPU（200）：12 %」。来源节点失败的末尾写「（节点失败）」，这时的值是失败前的最后一个值，不是结果。节点包的这个版本没有这张图表的写「这个版本的节点没有图表 X」，没有值的写「—」。读的是运行结束那一刻场景的关注项，不是触发时的。场景没有设关注项，或者这些关注项的节点都不在这次运行的版本里时，没有这一段，卡片和没有关注项时一样。
- 最后是「查看运行」按钮，打开这次运行。链接由控制面的 `SFLY_PUBLIC_URL` 拼出，没有配置时不显示按钮。

运行抽屉里有一行「运行通知」，显示这张卡片的状态：排队中、已送达、投递失败（写明原因）、已丢弃、未发送（写明原因，例如选中的机器人已被删除）。只是提示，从不改变运行的状态。运行还没结束、场景没有选机器人、结果不满足触发条件的运行没有这一行。

选中的机器人被删除后，设置弹窗里有提示，触发运行不会被拦截；运行结束时记为「未发送」。

「运行开始」的通知不属于运行通知：在入口节点后面放一个用 `ctx.notify` 发消息的节点，见下文。

## 在节点代码里发：`ctx.notify`

节点执行到一半就要通知（压测发现 p99 越界），用 `ctx.notify`：

```python
import sfly
from sfly import Context, FeishuBot, node


@node(outputs=["passed"])
def stress(ctx: Context, qps: int, alert_bot: FeishuBot) -> dict:
    p99 = 612.0  # 压测得到的延迟 99 分位（毫秒）；压测本身这里省略
    if p99 > 500:
        ctx.notify(alert_bot, f"p99 {p99} ms，超过 500 ms", at_all=True)
        ctx.notify(
            alert_bot,
            message=sfly.feishu.card("压测告警", f"**p99** {p99} ms，超过 500 ms", "red"),
        )
    ...
```

- 机器人要声明成 `FeishuBot` 类型的参数传进来（画布上是机器人下拉框，触发前检查它已登记；也可以点右侧的 `{}`（插入引用）改为引用入口参数，触发时再决定发到哪个群），不要在代码里写死名称，也不要自己请求 Webhook 地址。只发给这种参数引用的机器人，其他名称不发送，任务日志里有警告。
- 调用后立即返回，**投递失败永远不会抛出异常**，节点不会因为通知失败或变慢。投递结果写进这个任务的日志：送达是 info，失败或被丢弃是 warning。
- 本地调试（`sfly debug`）不真的发送，只把要发的请求体打印出来，不会骚扰群；单元测试里用 `sfly.testing.run_node` 结果的 `notifications` 断言每条消息的机器人和请求体。

完整的接口说明见 [开发节点（SDK 参考）](sdk-reference.md) 的「`ctx.notify`：飞书通知」。

### 三种格式

| 写法 | 发出的消息 |
|---|---|
| `ctx.notify(bot, text)` | 纯文本。`at_all=True` 时在正文末尾加上 `<at user_id="all">所有人</at>`。正文里自己写的 `<at user_id="ou_xxx">名字</at>` 原样发出，知道某人的 open_id 就能 @ 到他 |
| `ctx.notify(bot, message=sfly.feishu.card(title, markdown, color))` | 一张 Markdown 卡片：标题加颜色（`blue`（默认）、`green`、`orange`、`red`、`grey`），正文是 Markdown。不用手写卡片 JSON |
| `ctx.notify(bot, message={...})` | 原始消息：完整的飞书请求体，原样发出，不改写、不补字段。富文本、自己设计的卡片、模板卡片都走这一种 |

### 消息大小

飞书的请求体不能超过 20 KB（紧凑 JSON 按 UTF-8 编码的字节数，一个汉字 3 字节）：

- 文本：超过时截断正文，末尾加上「…（已截断）」，「@所有人」仍在最后。
- Markdown 卡片（`sfly.feishu.card`）：超过时截断 Markdown 正文，同样加上「…（已截断）」。标题长到连截断后的正文都放不下时，`sfly.feishu.card` 抛出 `ValueError`，开发时就会看到。
- 原始消息：**不截断**（截断会弄坏结构）。只校验它是一个对象、`msg_type` 是 `text`、`post`、`image`、`share_chat`、`interactive` 之一、不超过 20 KB；不合格的不发送，任务日志里写明原因，调用也不抛异常。图片消息只能用自己已有的 `image_key`，平台不上传图片。

### 放在链上的固定位置

想在运行开始、某一步之后或链尾发消息，做一个只发消息的节点，放进节点包，发布后像别的节点一样编排在链上：

```python
from sfly import Context, FeishuBot, node


@node(title="发飞书消息")
def notify(ctx: Context, bot: FeishuBot, text: str, at_all: bool = False) -> None:
    """把 text 发到飞书群。"""
    ctx.notify(bot, text, at_all=at_all)
```

- 运行开始时通知「压测开始」：放在入口节点后面。
- 链尾收尾：把它设为 always，不管前面成功还是失败都会执行。
- `text` 里可以写引用：输入 `$` 或点字段右侧的 `{}`（插入引用），选择入口参数或前面节点的输出，发出时替换成实际的值，所以消息里能带上目标 QPS、版本号这类值。
- 在链尾统一汇总各节点的状态和错误，再按结果发一条通知：正在规划，见 issue #452。

## 投递的规则

两种方式的消息进入同一个发送队列，由控制面投递：

- **按顺序**：同一个机器人的消息按产生的先后串行发出，不同机器人互不影响。
- **限速**：每个机器人每秒最多 5 条、每分钟最多 100 条，超出的排队等候。积压超过 1000 条时丢弃最旧的，一个失控的循环刷不爆群。
- **重试**：网络错误、超时、HTTP 429、5xx 和飞书的限流错误码 11232 会退避重试，间隔从 1 秒起逐次翻倍，最长 60 秒；从入队算起超过 10 分钟还没送达就记为失败。其他错误不重试，只发一次就记为失败。
- **不丢**：消息存在数据库里，控制面重启后接着投递。
- **结果在哪里看**：`ctx.notify` 的结果写进这个任务的日志（送达是 info，失败是 warning）；运行通知的结果显示在运行抽屉里；机器人页显示最近一次投递和积压条数。

## 群安全设置的常见错误

飞书的错误码会被翻译成中文，写明原因和下一步（测试消息、任务日志、机器人页的最近投递里都能看到）：

| 错误码 | 原因 | 怎么办 |
|---|---|---|
| 19021 | 群里的机器人开启了签名校验，sfly 不支持 | 在机器人的「安全设置」里关闭「签名校验」，改用「自定义关键词」或「IP 白名单」 |
| 19022 | 控制面的出口 IP 不在机器人的 IP 白名单里 | 把**控制面**访问飞书的出口 IP 加进白名单（不是 Agent 的 IP） |
| 19024 | 消息里没有机器人设置的关键词 | 每条消息都要包含群里设置的关键词之一：把关键词写进消息文本、卡片标题或运行通知的附加说明里，或者改用「IP 白名单」。测试消息里有「sfly」 |
| 9499 | 飞书认为请求格式不对 | 发原始消息时最常见：检查请求体是不是飞书要求的 JSON，`msg_type` 和 `content` 要对应；测试消息出现它时，检查 Webhook 地址是不是飞书机器人的地址 |
| 11232 | 触发了飞书的频率限制 | 自动退避重试，不用处理；飞书建议避开整点和半点发送，那时更容易被限流 |

其中 19021、19022、19024、9499 不重试，直接记为失败，修好群设置后再发。控制面连不上飞书（超时、连接失败）时，错误信息会提示检查网络（防火墙、DNS），见下文「部署时的出网要求」。

## 部署时的出网要求

这是控制面第一次主动向外发 HTTP 请求（ADR 0020）：

- **控制面所在的机器要能直接访问飞书**：官方飞书是 `open.feishu.cn` 的 443 端口；私有部署的飞书按登记的 Webhook 地址，控制面直接访问地址里的主机，不写死飞书域名。Agent 不需要出网。
- **不支持代理**，控制面必须能直接访问飞书。
- **IP 白名单填控制面的出口 IP**，不是 Agent 的 IP。
- **运行通知的「查看运行」按钮**需要 `SFLY_PUBLIC_URL` 配成浏览器能访问的控制面地址；时间显示用控制面所在的时区，设置 `TZ`。
- Webhook 地址当凭据保护：数据库里明文保存，数据库备份里有它；平台没有认证，能打开页面的人可以管理机器人。
